## 범위와 보관소 정정

운영 HA archive, 압축 전 archive 백업, 직접 수신기 전환 전 archive 백업을
읽기 전용(mode=ro, query_only)으로 조회했다. 차량 파일·원본 DB는 수정하지 않았다.
초기 조회는 운영 DB만 사용해 65건 중 10건만 상세 분석 대상으로 남겼다.
이는 전체 보유 기록이 10건이라는 뜻이 아니었다. 운영 DB 상세 상태는 10/20 이후이고,
압축 전 백업에는 9/20~10/4 상태 25,745건이 남아 있었다.

백업까지 합쳐 device/시작/종료 기준으로 중복을 제거하면 경계 누락도 포함한 요약 후보는
68개다. 실제 시계열 분석 후보는 29건: AC 13건, DC 16건이다. 그중 CAN 분류는
AC 7/DC 10건, 구형 속도 추정 분류는 AC 6/DC 6건이다. 구형 partial 플래그가 있는
10건도 실제 시계열 확인 대상으로 되살렸다. 29건 모두가 완충 기록이라는 의미는 아니다.

사용자 조건에 따라 AC 30분 미만은 제외한다. 요약 평균 전력(충전량/누적 확인시간)을
기준으로 11kW 초과는 DC 추정, 이하는 AC 추정으로 분류했다. 이는 기존 차량의 AC 한도를
사용한 연구용 추정이며 저출력 DC를 AC로 오분류할 수 있다. CAN 확인과 혼합하지 않는다.
실제 모드가 충돌하는 구간은 제외했다. AC 요약 평균만으로 충전기 정격을 추정하지 않는다.

후보 제외: 상세 표본 부족 20, AC 30분 미만 11, 추정에 필요한 요약 부정합 3,
CAN 모드 혼재 2, 명시적 신호 공백/보정 기록 1, 시작/종료 경계 누락 2.
상세 후보 조건은 경계와 첫/마지막 표본 차이 및 표본 간격 최대 180초,
유효 에너지·250kW 이하 증가율·SOC 비감소다. 이는 원격 archive의 해상도 기준이며
차량 수집기가 한순간도 멈추지 않았다는 보증이 아니다.

## 구형 partial의 구체적인 원인

당시 collector/engine.py의 `_sample_energy`는 다음 조건을 한 분기로 묶었다.

```python
if onroad or not prev or prev['onroad'] != onroad or not 0 <= now-prev['at'] <= 240:
    # 측정창 초기화
    if s.get('charge'):
        s['charge']['partial'] = True
```

`tick`은 이 함수를 호출한 뒤 `onroad` 여부로 충전 세션을 종료했다.
따라서 마지막 충전값 이후 바로 출발해도, **주행이라는 이유만으로** partial을 먼저
붙이고 종료할 수 있었다. 현재 저장소 코드와 9/14·9/19 Git 이력에서 이 순서를 확인했고,
정상 에너지·10초 후 주행을 입력해 True가 되는 것을 합성 재현했다.
이 분기의 원래 타당한 목적은 측정창을 가로질러 주행 에너지나 누락 시간의 충전량을
계산하지 않는 것이다. 하지만 측정창 초기화와 세션 전체의 결손 판정을 함께 처리했다.

다른 원인은 이전 에너지 표본 없음, 240초 초과 간격, 주행 상태 미확인,
250kW 초과의 비정상 에너지 증가였다. 원본에는 사유 코드가 없으므로 개별 레코드가
어느 원인으로 True가 됐는지는 플래그만으로 복원할 수 없다.

앞서 제시한 28건은 압축 전 백업의 구형 플래그 건수다. 운영 DB 구형 기록은 29건이며
두 집합은 완전히 같지 않다. 백업 28건 중 26건은 경과시간과 누적 확인시간 차이가
180초 이내, 나머지 2건은 약 3.5분/86.1분 차이다. 시간 합계 일치는 완전성의 증명이 아니다.

## 현재 기록기 수정

현재 Carrot의 CAN 기반 charge_recorder는 정상 출발만으로 partial을 붙이는
구형 분기를 이미 사용하지 않는다. 이 동작을 유지하고 회귀시험을 추가했다.
새 개선은 실제 결손 탐지와 이유 보존이다.

- 정상 CAN 충전 종료나 즉시 출발은 partial의 원인이 아니다. 주행 시 에너지를 더하지 않는다.
- 수집기가 멈춰 `update(None)`도 호출되지 않은 경우, 재개된 CAN 측정 시각과 마지막
  확인 시각의 90초 초과 간격을 탐지한다. 90초는 현재 차량 CAN 신선도 계약과 같다.
- 같은 모드로 돌아와 에너지를 제한적으로 복원해도 공백을 확인 충전시간에 합산하지
  않으며, 실제 관측이 빠진 기록은 partial과 unknown_duration_s로 보존한다.
- 배터리 잔량이 일정한 것과 잔량 관측 자체가 없는 것을 구분한다. 신선한 잔량이
  계속 수집되면 저출력·계단식 갱신만으로 partial이 되지 않는다.
- 중복 없는 partial_reasons에 신호 공백/타임아웃, 잔량 관측 공백, 초기 에너지 부재,
  비정상 에너지 증가, 경계 없는 충전 모드 전환 등의 이유를 저장한다.
- 기존 True인데 이유가 없는 상태는 legacy_reason_unavailable로 보존하며 임의 해제하지 않는다.

HA charge_costs 요약에도 사유를 보존한다. 수신 앱은 기존 텔레메트리 본문 전달 경로를
사용하므로 앱 코드·버전 변경은 없다. 에너지 계산이나 ETA 공식은 바꾸지 않았다.

## 실제 기록 재생

`scripts/replay_charge_completeness.py`는 비공개로 추출한 익명화 시계열을 시간순으로
수정 전/후 기록기에 넣는다. 종료 이후 5분 이내 관측된 비충전 CAN 또는 실제 driving
상태를 사용한다. 구형 기록은 사용자 승인에 따라 속도에서 추정한 모드를 입력하므로
CAN 직접 검증과 동등하게 해석하지 않는다. 원본 partial은 수정하지 않는다.

- 상세 후보 29건 중 종료 관측을 연결할 수 있는 26건 재생, 3건은 종료 미관측으로 보류.
- 과거 partial 기록 5건은 새 기록기에서 결손 사유 없이 정상 종료됐다. 구형 에너지 기반
  코드에서는 같은 실제 출발 입력으로 partial이 재현됐다. 원본 플래그의 숨은 원인이
  없었다는 증명이 아니라 정상 출발 오판 패턴의 재현이다.
- 26건 모두 수정 전후 계산 충전량이 같았다. 주행 에너지를 충전량으로 추가하지 않았다.
- 9건은 archive에서 90초 초과 관측 공백 등이 발견돼 새 모델이 partial 사유를 남겼다.
  이는 저장된 입력에 대한 재생 결과다. HA 전송 누락과 차량 내부 수집 중단은 다르므로
  이 9건을 실제 차량의 수집 장애라고 확정하지 않는다. 완전한 세션의 검증 표본으로 쓰지 않는다.

연속 관측/즉시 출발, 명시적 정지 후 출발, 수집 중단 후 재개·출발, 모드 신선/잔량 누락,
잔량 무변화, 공백 보정 후 결손 보존, 사유 중복 제거를 별도 합성 시험으로 검증했다.
합성 시험을 실차 재생 건수에 더하지 않는다.

## ETA 분석 결과와 추천

AC의 30분 뒤 실제 에너지 관측값을 임시 목표로 삼아 남은 시간을 예측했다.
시작 후 10분부터, 향후 약 30분이 남아 있는 각 측정 시점에서 평가했다.
80/100% 실제 도달시간 정확도로 바꿔 말하면 안 된다. 표본은 서로 겹치므로 독립 세션
개수는 AC 13건이며 개별 예측 수백 회를 수백 번의 독립 충전으로 세지 않는다.
아래는 탐색용 후보 전체의 세션별 MAE를 동일 가중한 값이다. 앞 절의 공백 진단 사례도
포함된 탐색치이므로 완전 세션만의 확증 시험이나 출하 승인 근거로 사용하지 않는다.

| 분류 | 최근 5분 에너지 증가율 | 최근 10분 증가율 | 최근 2분 전력 중앙값 |
| --- | ---: | ---: | ---: |
| CAN AC 7건 | 2.36분 | 1.80분 | 2.15분 |
| 속도 추정 AC 6건 | 1.16분 | 0.74분 | 2.58분 |

과거 정상 후보에는 초기 0~1.5kW, 2.0→6.0kW, 1.1→6.0kW 같은 상승 구간이 실제로 있다.
안정 구간도 약6kW와 약9kW가 모두 존재한다. 특정9.2kW를 고정 기준으로 쓰면 안 된다.
전력만 사용하도록 증가율을 버리자는 앞선 제안은 이 결과로 철회한다.

추천 AC 모델은 **상승 중에는 최근 실측 출력에 빠르게 반응하고, 안정 후에는 충분히 긴
에너지 증가율을 함께 사용하는 방식**이다. 10분은 현재 탐색에서 유망한 창 길이이지
모든 상황에 고정할 정답은 아니다. 출력이 실제로 변한 구간의 오래된 이력은 그대로
섞지 않아야 한다. 과거 기록은 초기 사전값·보정에 쓰고 현재 충전 출력이 들어오면 갱신한다.

DC는 기존 제공 커브를 유지하고 현재 실측 출력에 대한 커브 비율 보정을 검토할 근거가 있다.
CAN100%를 실제 통과한 1건(62→100%, 약43.1분)에서 시작 시점의 현재 모델 예측은
약33.8분, CAN SOC로 맞춘 커브 비례 보정 후보는 약44.7분이었다(오차 약-9.3/+1.6분).
하지만80%에서는 약15.7분 예측 대17.5분 실제로 더 짧았다. 단 한 세션이고 SOC 기준과
스무딩 방식도 다르므로 커브 비례 보정이 보편적으로 더 정확하다고 결론 내리지 않는다.
추가 완전 세션의 시간순 검증 후 반영한다. 온도별 커브를 안정적으로 학습할 자료는 부족하다.

CAN 표시 SOC와 에너지 목표 기준의 정합성은 별도 과제다. 현재64kWh를 다른 값으로
임의 변경하거나 CAN SOC로 저장 에너지를 덮어쓰지 않는다. 이번 요청에서 ETA 알고리즘을
운영 반영하지 않고, 먼저 기록 품질 수정과 관측 기반 검증을 마친다.
