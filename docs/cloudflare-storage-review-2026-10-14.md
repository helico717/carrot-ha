# Cloudflare 장기 저장 용량 검토 — 2026-10-14

## 판단

HA 무손실 압축 원칙은 재사용할 가치가 있으나 그대로 이식하는 것만으로는 장기 해결이
되지 않는다. 권장 방향은 반복 데이터 분리, 제한된 클라우드 보관, 무손실 압축,
용량 여유와 정리 검증, 전송 대기열 장애 격리의 조합이다. 운영 변경은 이번 검토에서
수행하지 않았다.

## 실측과 예측

- D1 실제 크기 499,998,720 bytes. telemetry_history 54,965행의 본문 합계
  440,754,890 bytes. 이 수치는 DB 전체와 다르며 인덱스·다른 테이블·페이지 공간을
  제외한다. 14일 초과 29,865행.
- 최근 14일 SQL 조건에 포함된 본문 합계 297,909,951 bytes. 날짜 경계와 미전송
  대기열이 있으며 완전한 14일 정상 수신량으로 보지 않는다.
- 10월 1일 1,386행/11,354,317 bytes: 평균 8,192 bytes.
  10월 13일 1,806행/28,193,896 bytes: 평균 15,611 bytes.
- 현 최근 최대 본문 15,685 bytes를 고정한다고 가정하면 60초 간격 1,440행/일은
  14일 316MB, 30초 간격 2,880행/일은 632MB. 본문만의 시나리오이며 실제 주행/
  주차 혼합·기기 수·상태 전환·재시도·인덱스·설정·주행 경로를 추가해야 한다.
- 압축률 50% 가정은 위 값을 158~316MB로 줄이지만 D1 실측 결과가 아니다.
  HA의 415→213MB 결과는 SQL projection+압축 원문을 보존하는 HA 전용 구조다.
  행 크기와 압축률이 변하거나 보관 정리가 실패하면 다시 한도에 도달한다.

## 구현 선택

1. 정리만 복구: 필수지만 원문 크기의 성장 때문에 단독으로 충분하지 않다.
2. 압축만 도입: 수명을 늘리지만 무제한 누적을 해결하지 못하며 Worker CPU와
   변환/복원 호환성 검증이 필요하다. HA Python 파일을 Worker에 그대로 복사할 수 없다.
3. 권장 조합: 클라우드는 최신 상태와 제한된 동기화 이력을 제공하고 HA는 현재처럼
   장기 기록을 보존한다. 기존 14일 보관을 출발점으로 실제 바이트 예산을 검증한다.
   본문을 무손실 압축하고 충전 목록·월별 집계 등 반복 데이터는 장치/버전별로
   별도 저장해 역사 시점의 정확한 참조가 가능하게 한다. 최신 값으로 과거를 덮어쓰지 않는다.
4. 유료 상향/외부 장기 원본 저장: 기기 수나 오프라인 보존 요구가 커질 때 검토할 수
   있으나 무제한 누적과 대기열 장애를 해결하는 대체 수단으로 삼지 않는다.

## 장기적으로 필요한 경계

- 500MB 도달 전 충분한 여유에서 정리. 예: 전체 DB 정상 목표 300MB 이하와
  350MB 경보는 초기 설계 제안이며 검증된 안전 한도가 아니다. 텔레메트리·주행·
  설정·인덱스별 예산을 실측으로 정하고 정리 주기 사이의 최악 유입량을 포함한다.
- 예약 실행 설정을 코드로 관리하고 실제 원격 예약·성공 시각·삭제 건수·용량 효과를
  검증한다. 날짜 형식을 통일하고 배치 크기를 제한한다. 삭제/압축 후 바이트 회수와
  재사용 여부는 D1 운영 환경에서 별도 검증하며 HA VACUUM 동작을 가정하지 않는다.
- HA에 아직 수신되지 않은 자료를 용량 목표 때문에 임의 삭제하지 않는다. HA 장기
  보관을 유지하고 장치별 커서/재전송/중복 ACK/보관기간 초과 오프라인 정책을 명시한다.
  안전하게 정리할 자료가 없으면 경보·명시적 거절/기기 보존으로 처리하고 성공 ACK로
  손실을 숨기지 않는다. 연속 커서가 누락 자료를 건너뛰지 않게 한다.
- 압축 저장은 버전 envelope, 압축/해제 크기 상한, 기존 raw_json 응답의 완전 복원,
  기존 비압축 행 읽기 호환성, SHA/원문 동등성을 보장한다. 최신 상태 경로에 이력
  압축/대량 정리를 추가하지 않는다. HA projection의 중복 원문 구조를 D1에 복제하지 않는다.
- 일반 주행·상태·영상 파일 송신은 진행을 서로 차단하지 않는다. 동일 outbox 선두의
  상태 실패가 주행까지 막는 현재 현상은 별도의 개선 대상이다. 실패 자료는 보존하며
  각 종류의 제한된 재시도·우선순위·공정성을 검증한다.
- 압축은 행 수 과금을 줄이지 않는다. INSERT/UPDATE/DELETE와 인덱스 쓰기,
  예약 정리·실패 재시도·마이그레이션을 포함한 계정 전체 reads/writes/CPU를 측정한다.
  DB 한 개의 수치만으로 무료 플랜 영구 보장을 주장하지 않는다.

## 통과 기준과 미확인

실제 D1 표본 압축률·복원 동등성·페이지 효과, Worker CPU/응답 시간, 다기기와
연속 주행 유입량, 정리 실패 후 복구, HA 장기 오프라인 뒤 catch-up, 최신 상태 경로
독립성과 주행 대기열 격리를 검증한다. 기존 인증/격리/증분 커서/무료 플랜 회귀 게이트를
유지한다. 운영 24시간 관찰과 보관 주기 이후 용량 안정화 확인 전 장기 안정으로 보고하지 않는다.
