# 인터랙티브 3D 차량 (선택 기능)

내 차 탭의 차량 이미지를 3D 모델로 바꿔, 문·트렁크·하향등·주행 상태를 실시간으로 보여 줍니다.
**모델 파일은 저장소에 포함되어 있지 않습니다.** 사용자가 직접 준비한 파일을 HA 서버에 두었을 때만 동작하며,
파일이 없거나 WebGL을 쓸 수 없으면 기존 정적 이미지가 그대로 표시됩니다.

## 설치

1. 모델 파일(`vehicle.glb`)을 HA 서버의 `/config/carrot_ha/models/vehicle.glb`에 둡니다.
2. **HA를 재시작**합니다. (폴더는 시작 시점에 한 번만 등록됩니다.)
3. 브라우저를 강력 새로고침(Ctrl/Cmd+Shift+R)합니다.

모델 파일을 제3자에게 재배포하지 마세요. 모델마다 라이선스가 다르며, 이 저장소는 모델 파일을 커밋하지 않도록
`.gitignore`(`*.glb`)로 막아 두었습니다.

## 카드 옵션

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `vehicle_3d` | 자동 | `false`이면 3D를 끄고 정적 이미지만 사용 |
| `vehicle_3d_model` | `/carrot_ha_models/vehicle.glb` | 모델 주소를 바꿀 때 사용 |
| `vehicle_3d_color` | `#333234` | 차체 색 (예: `#333234`는 RGB 51, 50, 52) |

## 보이는 상태와 기본 시점

대시보드가 이미 가지고 있는 값만 사용하므로 클라우드·HA에 새 요청을 만들지 않습니다.

| 상태 | 기본 시점 | 사용하는 값 |
| --- | --- | --- |
| 주차(문 닫힘) | 전면 | — |
| 주차 + 문/트렁크 열림 | 45° 탑뷰, 열린 문 표시 | `door_*_open`, `trunk_open` |
| 주행 중 | 뒤쪽 위 3/4 시점, 바퀴 회전·도로 이동 | 주행 상태, `speed_kph` |
| 하향등 켜짐 | 후미등·하향등 발광, 바닥에 부채꼴 빛 | `light_low_beam_requested` |

- 하향등 값은 **하향등 요청** 신호이며 전구의 실제 점등이 아닙니다. 차량이 잠들면 180초 후 만료되어 켜진 채로 남지 않습니다.
- 문 열림 각도 센서가 없어 열림/닫힘 두 상태만 표현합니다.
- 상태가 바뀌면 카메라는 그 상태의 기본 시점으로 돌아갑니다.

## 충전 중 표시

카드가 차량을 **충전 중**으로 표시할 때만 켜지는 장면입니다. 주행이 시작되거나 충전이 끝나면 사라지고 원래 시점으로 돌아갑니다.

- **X-ray 차체:** 차체와 창문은 10%, 바퀴·타이어는 30%만 보이고 실내는 숨깁니다. 열린 문과 트렁크는 84% 불투명에 호박색으로 강조합니다. 문이 팩 앞에 있으면 팩을 가리고, 뒤에 있으면 팩에 가려집니다.
- **배터리 팩:** 앞뒤 차축 사이 차대 아래에 평평하게 놓입니다. 후방에서 전방으로 SOC(`soc_percent`)만큼 초록으로 채워지며, 가로 3×세로 12 모듈 격자가 보입니다. 크기와 위치는 일반적인 ID.4 기준의 추정치입니다.
- **케이블과 충전기:** 충전기 기둥(화면에 SOC와 kW 표시)에서 케이블이 나와 충전구의 커넥터로 이어집니다. 커넥터는 위에서 아래로 30° 기울어 꽂힙니다. 충전구에서 팩까지는 차대를 따라가는 초록 선 두 가닥입니다. 충전구 위치는 이 모델의 오른쪽 뒤 펜더(눈대중)입니다.
- **스윕:** 빛 한 줄기가 충전기, 케이블, 충전구, 초록 선, 채워진 팩 순서로 한 바퀴 돕니다. **11kW 이하는 4.4초, 초과는 2.2초**에 한 바퀴이며 대시보드 SOC 바의 스윕 주기와 같습니다. 전력 값(`charge_power_kw`, 없으면 `charge_power_w`)이 없을 때는 `charge_mode`가 `dc_charging`이면 빠른 쪽을 씁니다.
- **하향등:** 충전 중에는 실제 하향등 값과 무관하게 헤드램프·테일램프가 켜진 모습으로 보이고, 충전이 끝나면 실제 값으로 돌아갑니다. 주행이 시작되면 충전 효과가 꺼지고 실제 값을 따릅니다.
- **시점:** 충전 중 기본 시점은 오른쪽 앞 3/4(`charge`)이며 문이 열려도 이 시점을 씁니다. 드래그로 돌려 보는 것은 다른 상태와 같습니다.
- **디버그 대시보드:** 충전 시나리오 13개(완속 7kW, 11kW 경계, 급속 50kW, 150kW, SOC 10%·95%, 문·트렁크 전부 열림, 하향등 복원, 충전 중 주행 시작 등)가 `전체 순회 재생`에 들어 있고, 시점·램프 밝기·스윕 속도 등급을 자동으로 검사합니다. 디버그의 150kW 시나리오는 충전 곡선 때문에 실제 표시 전력이 95kW 안팎이며, 어느 쪽이든 11kW를 넘으므로 빠른 스윕입니다.

## 조작

- 드래그: 모든 방향으로 회전합니다. 위쪽, 좌우에는 제한이 없고, 카메라는 차 중심 높이의 수평선 아래로만 내려가지 않습니다.
- 더블클릭: 현재 상태의 기본 시점으로 돌아갑니다.
- 확대·축소: Ctrl+휠 또는 트랙패드 핀치, 터치 핀치. 차량 위의 일반 휠·트랙패드 스크롤은 페이지로 전달하지 않습니다. 페이지를 스크롤하려면 차량 바깥 영역을 사용합니다.
- 모바일: 차량 위의 가로·세로 드래그는 회전입니다. 차량에서 시작한 스와이프는 페이지를 스크롤하지 않습니다. 차량 바깥에서는 기존처럼 화면을 스크롤합니다.

## 성능과 안전

- **첫 방문**에는 모델(약 2MB)과 3D 모듈(약 0.6MB)을 내려받습니다. 두 전송은 대시보드 데이터 요청과 **동시에** 시작합니다.
- **이후 방문**에는 브라우저의 IndexedDB에 저장한 모델 사본을 바로 사용하므로 모델 전송을 기다리지 않습니다. 백그라운드에서 ETag로 변경 여부만 확인하고, 모델 파일을 바꿨다면 **다음 방문**부터 새 파일을 씁니다. (localStorage는 용량이 작고 바이너리에 부적합해서 쓰지 않습니다.)
- HA 서버와의 회선이 느리면 첫 방문이 오래 걸릴 수 있습니다(예: 약 100KB/s에서 모델 20초 이상). 저장본이 생긴 뒤에는 영향이 없습니다.
- 3D 모듈과 모델은 내 차(개요) 카드가 있을 때만 불러옵니다. `vehicle_3d: false`이면 아무것도 내려받지 않습니다.
- 카드가 보이지 않거나 브라우저 탭이 숨겨져 있으면 렌더링을 멈춥니다. 움직임이 없을 때도 매 프레임 그리지 않습니다.
- 갱신 때 캔버스를 다시 만들지 않고 상태만 전달하므로 스크롤·시점이 유지됩니다.
- 모델 파일 요청 외에 어떤 요청도 만들지 않습니다. 모델이 없으면 404를 한 번 받고 이미지를 유지합니다.

## 모델 만드는 방법(참고)

현재 모델은 서로 다른 출처의 부품을 합쳐 만들었고 `tools/vehicle3d/model/`의 스크립트로 다시 만들 수 있습니다.
입력 파일은 저장소에 없으며 `MODEL_WORK` 폴더(기본 `./work`)에 직접 두어야 합니다.

1. `source.glb`: 문 4개·트렁크 애니메이션(`Front left door` 등)이 분리된 차체 모델
2. `second.glb`: 테일램프 디자인을 가져올 모델 (`Red_Light22` 메시 등)
3. `meshy_wheel.glb`: 휠 형상, `wheel_photo.png`: 휠 정면 사진(색 투영용)

```bash
cd tools/vehicle3d/model && npm install
MODEL_WORK=./work node prepare_wheel.mjs 30000
MODEL_WORK=./work node build_model.mjs 0.35 0.002 8
```

결과는 `work/vehicle.glb`입니다. 텍스처는 `sharp`가 설치되어 있으면 WebP로 압축하고(약 2MB), 없으면 PNG로 남습니다(약 3.5MB). 이를 위의 설치 위치에 복사합니다. 뷰어(`carrot-assets/vehicle-3d.js`)는
`tools/vehicle3d/viewer.src.js`에서 `tools/vehicle3d/build.sh <node_modules 경로>`로 만듭니다.

사용한 외부 모델의 출처와 조건:

- 차체: Sketchfab 「Volkswagen ID.4 Pro (2025)」 geyges, Sketchfab Standard 라이선스(개인 사용)
- 테일램프: Sketchfab 「2022 Volkswagen ID4」 BloxBloger, CC BY-NC 4.0 (저작자 표시, 비영리)
- 휠 형상: Meshy로 생성한 모델. 사용 조건은 Meshy 약관을 확인하세요.

## 알려진 한계

- 모델·휠 사진의 해상도와 실제 차량과의 차이(휠 스포크 방향, 테일램프 세부)는 눈으로만 비교했습니다.
- 휠의 깊이는 타이어에 맞추려고 의도적으로 눌려 있으며, 타이어 안쪽은 어두운 통으로 막혀 있습니다.
- 디버그 대시보드도 같은 3D 뷰어를 사용합니다. 문·트렁크·하향등·속도·폴백과 22개 시나리오를 가상 값으로 시험할 수 있습니다. [러브레이스 추가와 사용 안내](DEBUG_DASHBOARD.md)를 참고하세요.
