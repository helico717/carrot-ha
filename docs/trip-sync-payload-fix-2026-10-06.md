# 긴 주행 이력 동기화 실패 — 2026-10-06

HA SSH 읽기 전용 검사에서 최신 차량 상태는 계속 저장되지만 긴 주행은 HA에
저장되지 않는 현상을 확인했다. 클라우드 주행 변경 응답은 정상이며 설치된
변환 함수에서 `ValueError: Payload too large`를 재현했다. 변환된 이벤트는
262,161 bytes로 262,144 bytes 제한을 17 bytes 초과했다.

원인은 정규화된 route와 cloud_raw_trip.route의 동일 경로 중복이다.
경로 전체를 data.route에 한 번 보존하고 진단 메타데이터에서는 동일 경로만
제거한다. route_json도 정규화 경로와 동일할 때만 제거한다. 입력 객체를
변경하지 않으며 크기 제한과 차량 격리는 그대로 유지한다.

HA 최신 상태 조회 성공 시각을 별도로 기록하고 연결 엔터티가 이를 참조한다.
주행/아카이브 실패는 기존 오류 상태와 커서를 유지하지만 독립적으로 성공한
최신 조회를 가리지 않는다. 180초 확인 제한과 300초 차량 측정 제한을 유지하여
클라우드 확인만으로 오래된 차량 데이터를 신선하다고 처리하지 않는다.

수정 함수를 HA 메모리에서만 실행해 실제 실패 응답의 parse 성공을 확인했다.
운영 DB 직접 수정이나 커서 수동 이동은 하지 않았다. 재시작 후 정상 증분
동기화가 저장한 뒤 커서를 전진시키도록 한다.

검증: HA Python 299 tests 통과(3 skip), 최신/lazy/view-state JS 10 tests 통과,
Worker incremental 및 benchmark 통과, Comma param polling 4 tests 통과.
Cloudflare/Comma 코드 및 Worker/D1 배포 변경 없음. 실기 복구는 사용자 HA
재시작 후 DB와 화면으로 별도 확인한다.
