# 오픈파일럿 사용 통계 — 백엔드 구현 계획서 (2026-11-05, 2차 검토 반영)

상태: **계획 단계. 코드 변경·배포 없음.** 화면(프론트엔드)은 이 계획의 데이터가 쌓인 뒤 별도로 설계한다.
화면 변경 시에는 AGENTS.md 7절에 따라 인터랙티브 HTML 프리뷰 승인을 먼저 받는다.

## 1. 무엇을 만들려는가

테슬라 FSD 통계 화면처럼 다음 값을 **주행별**과 **통계 시작 이후 누적**으로 보여 줄 수 있게 데이터를 모은다.

| 보여 줄 값 | 예 |
|---|---|
| 오픈파일럿 보조로 주행한 거리 | 303 km |
| 보조 없이(수동) 주행한 거리 | 6 km |
| 보조 사용 비율 | 98.1 % |
| 최장 연속 보조 주행 거리 | 44.6 km |
| 연속 사용 일수, 일·월별 막대그래프 | 4일 연속 |
| 보조 켜짐·해제 횟수 (1초 표본 기준) | 켜짐 5회 / 해제 4회 |

## 2. 지금 상태 (코드로 확인한 사실)

- Comma 수집기는 1초마다(`time.sleep(1)`) `selfdriveState.enabled`를 읽고, 수신 후 10초까지 같은 값을 재사용한다.
  이 값은 **현재 상태 묶음(telemetry)에만** 30초마다 실린다. 주행 기록(trip)에는 보조 상태가 없다.
- 주행 거리는 **CAN 휠 속도 × 단조 시계**로 1초마다 쌓는다(`engine.py`의 `distanceM`). GPS는 지도 경로에만 쓴다.
- 휠 적산이 불완전하면 주행거리계로 복구한다. 이때 복구값은 휠 적산보다 **최대 2km 작을 수도 있다**
  (`odo_m >= distanceM - 2000`, 주행거리계는 1km 단위).
- 실제 조향 보조는 `selfdriveState`와 다를 수 있다. `controlsd.py`에서 `carControl.latActive`는 상시 조향 설정이면
  `selfdriveState.active`가 꺼져도 켜질 수 있고, Carrot 조향 일시 중지(`lat_suspend_control`)에서는 꺼진다.
  `longActive`는 가속 페달 개입 때 꺼진다. `selfdriveState`와 `carControl`은 모두 100Hz로 나온다.
- 수신 앱은 같은 주행 ID가 다시 오면 원본을 지우고 새로 넣는다(`receiver.py`의 `receive()`).
  `tripMeasurements`와 `partial`만 이전 값을 보존한다. HA로 보내는 `trip()` 응답은 정해진 항목만 내보낸다.
- HA는 주행 기록을 **기본 90일 뒤 삭제**한다(`storage.py`의 `purge_expired(trip_days=90)`).
  수신 앱도 HA가 받아 간 기록을 지운다. 따라서 누적 통계는 **주행 기록과 별도로 영구 보관**해야 한다.

**결론:** 지금 데이터로는 30초 간격의 거친 추정만 가능하다. 정확한 값은 수집기를 고친 **이후 주행부터** 쌓인다.

## 3. 핵심 원칙

2026-09-25~26 터널 거리 작업(커밋 `19b936c`, `f46fd29`)의 원칙을 그대로 따른다.

1. **거리는 차량 신호로만 잰다.** 보조 거리도 전체 거리와 같은 1초, 같은 휠 속도, 같은 시간 간격으로 더한다.
   터널에서도 정확하다.
2. **모르는 구간을 추측으로 메우지 않는다.** 신호가 끊긴 구간은 "켜짐"이나 "꺼짐"이 아니라 "상태 모름"이다.
3. **원본은 고치지 않는다.** 한 번 저장된 유효한 통계는 나중에 온 본문이 덮어쓰지 못한다.

## 4. 판정 기준 — 무엇을 "보조 주행"으로 보는가

### 4-1. 대표 지표: `carControl` 한 메시지로 판정

`latActive`와 `longActive`는 같은 `carControl` 메시지에 들어 있으므로, 한 표본을 네 칸 중 하나로 나눈다.

| `latActive` | `longActive` | 칸 |
|---|---|---|
| 꺼짐 | 꺼짐 | 수동 |
| 켜짐 | 꺼짐 | 조향만 |
| 꺼짐 | 켜짐 | 가감속만 |
| 켜짐 | 켜짐 | 둘 다 |

- **보조 거리 = 조향만 + 가감속만 + 둘 다.** 각 표본은 한 칸에만 들어가므로 중복이 없다.
- `carControl`을 2초 넘게 받지 못하면 그 구간은 대표 지표에서 **상태 모름**이다.

### 4-2. 보조 지표: `selfdriveState.enabled` (시스템 활성)

- "시스템 활성 거리"라는 이름으로 따로 집계한다. 기존 HA의 "주행 보조 활성" 센서와 같은 기준이다.
- `selfdriveState`만 2초 넘게 끊기면 **이 지표만** 상태 모름이 되고 대표 지표에는 영향이 없다.
- 2초 유효기간은 **새 통계 판정에만** 적용한다. 기존 텔레메트리의 `enabled` 표시(10초)는 바꾸지 않는다.

### 4-3. 1초 구간을 어느 칸에 넣는가

1초마다 기존 코드가 휠 속도로 이번 구간의 거리(`증가분`)를 더할 때, **직전 표본의 칸**에 같은 `증가분`을 더한다.
직전 표본이 없거나 만료됐으면 상태 모름에 더한다. 기존 코드가 거리를 더하지 않는 공백(3초 초과, 이상한 속도)에는
어느 칸에도 더하지 않는다.

## 5. 거리 계산식 — 휠 적산 기준과 최종 거리를 분리

### 5-1. 두 가지 거리

- **기준 거리(`basisDistanceM`)**: 휠 속도로 실제 적산한 거리. 네 칸과 신호 모름의 합과 항상 같다.

  ```text
  기준 거리 = 수동 + 조향만 + 가감속만 + 둘 다 + 신호 모름
  ```

- **최종 거리(`distanceM`)**: 주행 기록의 최종 거리. 주행거리계 복구나 HA 거리 보정으로 기준 거리와 달라질 수 있다.
- **복구 차이** = 최종 거리 − 기준 거리. **음수일 수 있다.** 세 칸 값은 이 차이 때문에 바뀌지 않는다.

### 5-2. 사용 비율 (분모 고정)

```text
사용 비율 = 보조 거리 ÷ (보조 거리 + 수동 거리)
```

- 상태 모름과 복구 차이는 **분모에 넣지 않는다.**
- 분모가 0이면 "측정 안 됨"(`null`)으로 반환한다. 0%로 표시하지 않는다.
- 화면의 "상태 모름 거리" = 신호 모름 + max(0, 복구 차이). 복구 차이가 음수면 그 값을 따로 기록만 한다.

### 5-3. 기준 예시 (그대로 테스트에 넣는다)

| 휠 적산 | 최종 거리 | 사용 비율 | 복구 차이 | 상태 모름 표시 |
|---|---|---|---|---|
| 보조 8km, 수동 2km | 12km (복구) | **80%** | +2km | 2km |
| 보조 8km, 수동 2km | 9km (하향 복구) | **80%** | −1km | 0km (차이 −1km 별도 기록) |

## 6. 켜짐·해제 횟수와 연속 구간

### 6-1. 횟수 (1초 표본 기준)

- **켜짐 1회**: 연속된 두 유효 표본이 수동 → 보조로 바뀔 때만 센다.
- **해제 1회**: 연속된 두 유효 표본이 보조 → 수동으로 바뀔 때만 센다.
- 주행 시작 첫 표본, 공백 뒤 다시 받은 표본(모름 → 보조, 모름 → 수동)은 **세지 않는다.**
- 1초 안에 해제했다 다시 켠 경우는 놓친다. 별도 전환 수집기는 만들지 않으며, 화면과 문서에
  "1초 표본 기준"이라고 표시한다.

### 6-2. 연속 보조 구간

- 보조 상태로 달린 거리를 현재 구간에 더한다.
- 수동으로 바뀌거나, 상태 모름이 되거나, 거리 계산이 끊기거나, 주행이 끝나면 구간을 마감한다.
  공백 때문에 마감했으면 `brokenByGap: true`를 남긴다. 그래서 최장 기록은 짧게 나올 수는 있어도 부풀려지지 않는다.
- 주행별로 마감된 구간 목록을 남긴다: `{startAt, endAt, distanceM, brokenByGap}`.
  100m 이상 구간만, 거리순으로 최대 50개까지 남긴다(정확한 개수는 `streakCount`에 따로 남긴다).
- **기간별 최장 연속 거리는 구간 시작 시각이 속한 기간에 귀속한다.** 자정을 넘겨 이어진 구간은 거리 전체를 시작일에 인정한다.
  일별 막대 합계(시간 구간 소계)와는 별개 기준이며 문서와 화면에 명시한다.

## 7. 날짜 귀속 — UTC 15분 구간 소계

- 주행별로 **UTC 15분 단위 소계**를 남긴다: `{at, manualM, latOnlyM, longOnlyM, bothM, unknownM}`.
  `at`은 UTC 15분 경계 시각이다.
- 1초 구간이 15분 경계에 걸치면 `증가분`을 경계 앞뒤 **시간 비율로 나눈다.** 그래서 구간 소계의 합은 항상 기준 거리와 같다.
- HA가 자기 시간대로 일·월에 나눈다. 한국 시간의 자정·월말은 UTC 정시 경계라 정확하다.
  실제로 쓰이는 시간대 차이는 모두 15분 단위이므로, UTC+05:30·+05:45 같은 시간대도 현지 자정에서 정확히 나뉜다.
- 3시간 주행이면 12줄, 줄당 숫자 6개다.
- 복구 차이(양수)는 주행 종료 시각이 속한 날에 "상태 모름"으로 더한다.

## 8. 단계별 작업

### 8-1. Comma 수집기 (`helico717/openpilot`, `carrot-wip-model_selector-ha`, `selfdrive/carrot/ha/`)

1. `collector.py`: `SubMaster`에 `carControl`을 추가한다. `latActive`·`longActive`와 `selfdriveState.enabled`를
   각각 수신 후 2초 이내일 때만 유효 표본으로 엔진에 넘긴다.
2. `engine.py`: 기존 거리 적산 바로 옆에서 4장·6장·7장 규칙으로 누적한다. 값은 주행 상태(`trip`) 안에 두므로,
   5초마다 저장되는 상태 파일에 함께 남아 재시작 후에도 이어진다. 재시작·공백 때는 기존 `last_motion`처럼
   직전 표본을 지운다(공백 뒤 재관측을 켜짐으로 세지 않기 위해).
3. 주행이 끝나면 기록에 `assist`를 추가한다.

```json
"assist": {
  "version": 1,
  "basisDistanceM": 309000.0,
  "manualM": 6000.0, "latOnlyM": 0.0, "longOnlyM": 0.0, "bothM": 303000.0, "unknownM": 0.0,
  "knownDurationS": 15000, "assistDurationS": 14200,
  "enabled": {"onM": 303000.0, "offM": 6000.0, "unknownM": 0.0},
  "engagements": 5, "disengagements": 4,
  "streakCount": 6,
  "streaks": [{"startAt": "2026-11-05T01:02:03+00:00", "endAt": "2026-11-05T01:40:00+00:00",
               "distanceM": 44600.0, "brokenByGap": false}],
  "buckets": [{"at": "2026-11-05T01:00:00+00:00", "manualM": 120.0, "latOnlyM": 0.0,
               "longOnlyM": 0.0, "bothM": 9800.0, "unknownM": 0.0}]
}
```

- `version`은 **계산 방식의 버전**이다. 같은 주행의 정정 번호가 아니다(9장).
- 구현(openpilot `carrot-ha-assist-stats` `7862875`)에서는 위 항목에 `longestStreakM`·`longestStreakS`를 더 넣는다.
  100m 미만 구간까지 포함한 주행 내 최장 연속 거리·시간이며, `streaks` 목록에는 100m 이상만 남는다.
- 100m 미만 주행은 지금처럼 전송하지 않는다(11장 결정 사항).

### 8-2. 수신 앱 (`addons/carrot_receiver/receiver.py`)

- 테이블 변경은 없다(원본을 통째로 저장한다).
- `trip()` 응답에 `assist`를 추가하고 검증한다. 모든 값이 0 이상의 유한한 숫자여야 하고,
  다섯 칸의 합과 구간 소계의 합이 모두 기준 거리와 같아야 하며(반올림 1m 허용), 연속 구간 거리는 보조 거리 이하여야 한다.
  **최종 거리와는 비교하지 않는다.** 검증에 실패하면 `assist: null`과 실패 이유를 내보내고, 주행 기록 자체는 그대로 둔다.
- 재전송 규칙은 9장을 따른다.
- 앱 버전과 `addons/carrot_receiver/CHANGELOG.md`를 갱신한다.

### 8-3. HA 통합 (`custom_components/carrot_ha/`)

1. **받기**: `cloud_feed.py`가 `assist`를 함께 넘긴다.
2. **영구 요약 테이블** (주행 기록 삭제 `purge_expired` 때 지우지 않는다):
   - `assist_trips`: 주행 1건당 1줄. 기기, 주행 ID, 시작·종료 시각, 버전, 기준 거리, 최종 거리, 다섯 칸, 시스템 활성 칸,
     횟수, 본문 해시, 충돌 횟수.
   - `assist_buckets`: (기기, 주행 ID, UTC 15분 시각)당 1줄.
   - `assist_streaks`: (기기, 주행 ID, 시작 시각)당 1줄.
   - `assist_meta`: 기기별 통계 시작 시각, 시작 시점의 주행거리계 값과 측정 시각.
3. **저장 원자성**: 주행 원본과 영구 요약을 **같은 트랜잭션**에 저장한다. 페이지 전체가 저장된 뒤에만 동기화 커서를 움직인다
   (AGENTS.md 8절). 키가 같으면 덮어쓰기만 하므로 같은 페이지를 다시 받아도 두 번 세지 않는다.
4. **집계 함수**: 기간(전체·연·월·주·일)별로 다섯 칸 합계, 사용 비율(5-2), 시스템 활성 거리, 최장 연속 거리(6-2),
   켜짐·해제 횟수, 연속 사용 일수, 월별 합계. 일·월은 HA 시간대로 15분 구간을 나눈다.
   **"사용한 날"은 그날(HA 시간대)의 보조 거리가 1km 이상인 날이다.** 연속 사용 일수는 이런 날이 끊기지 않고 이어진 일수다.
5. **기록되지 않은 거리(추정)**: 통계 시작 이후 유효한 주행거리계 두 측정 시각 사이의 차이에서, 같은 기간에 끝난 주행의
   최종 거리 합을 뺀다. 100m 미만 주행·업로드 대기 주행·Comma가 꺼진 주행이 모두 여기 섞이므로
   "Comma가 꺼진 거리"로 부르지 않는다. 늦게 도착한 주행이나 HA 거리 보정이 생기면 다시 계산하고 캐시를 무효화한다.
   주행거리계 값이 이상하면 계산하지 않는다(기존 검증 기준 재사용).
6. **기존 거리 보정과의 관계**: `trip_repair.py`가 최종 거리를 바꾸면 복구 차이만 다시 계산한다. 다섯 칸은 바꾸지 않는다.
7. **공유와 성능**: 결과는 HA 안에서 한 번 계산해 모든 카드가 공유한다. 화면마다 수신 앱에 따로 묻지 않는다(AGENTS.md 8절).
8. **조회 경로**: 화면용 API 하나. 원하면 HA 센서(누적 보조 거리, 누적 사용 비율)도 추가한다.
9. **`assist`가 없는 주행**: 과거 주행과 Comma 업데이트 전 주행은 "측정 안 됨"으로 집계에서 뺀다.
   30초 간격 상태 기록으로 추정치를 만들지 않는다(사용자 결정, 12장).
10. **통계 시작일**: 처음으로 `assist`가 들어온 주행의 시작 시각. 누적 통계와 "기록되지 않은 거리(추정)"는 이날부터 계산한다.

## 9. 같은 주행이 다시 올 때 (첫 버전은 정정 미지원)

Comma는 주행이 끝날 때 `assist`를 한 번 계산하므로, 같은 주행이 다시 오는 경우는 업로드 재시도와 기록 갱신뿐이다.
첫 버전에서는 정정을 지원하지 않고 다음 규칙만 지킨다. 수신 앱과 HA 양쪽에 똑같이 적용한다.

| 새로 온 본문 | 처리 |
|---|---|
| `assist` 없음, 기존 값 있음 | 기존 값 보존 (`tripMeasurements`와 같은 방식) |
| 기존과 같은 값 | 무시 (변경 아님) |
| 같은 버전, 다른 값 | **기존 값 보존**, 충돌 횟수 +1, 로그 기록 |
| 검증 실패 값 | 기존 값 보존. 기존 값이 없으면 `null` |
| 첫 유효 값 | 저장 |

정정이 필요해지면 송신자가 매기는 주행별 `revision`을 따로 도입한다. 그때는 높은 정정본 뒤에 옛 본문이 다시 와도
값이 되돌아가지 않는지 테스트해야 한다.

## 10. 테스트 계획

**인수 테스트 (먼저 만든다)**

1. 휠 적산 > 복구 거리: 5-3의 9km 예 → 사용 비율 80%, 복구 차이 −1km, `assist`가 검증을 통과.
2. 복구 거리 > 휠 적산: 5-3의 12km 예 → 사용 비율 80%, 상태 모름 2km. 모름이 분모에 섞이지 않는지.
3. `enabled=false` + `latActive=true` → 조향만 칸, 시스템 활성 지표는 꺼짐.
4. 보조를 유지한 채 `carControl` 신호 단절·복귀 → 켜짐 횟수 그대로, 구간은 `brokenByGap`으로 마감.
5. 유효한 주행 뒤 `assist` 없는 같은 ID 재전송 → 기존 값 보존. 같은 버전의 다른 값 재전송 → 기존 값 보존, 충돌 +1.
6. 자정·월말을 넘는 주행 → 경계에 걸친 1초 구간이 시간 비율로 나뉘고, 양쪽 날짜 합 = 기준 거리.
   자정을 넘긴 연속 구간은 시작일의 최장 기록으로 잡힘.
7. 저장 중단: 한 페이지의 첫 주행은 저장되고 두 번째 주행의 요약 저장에서 실패 → 커서 유지 → 같은 페이지 재수신 →
   두 주행이 각각 **한 번만** 집계.

**추가 테스트**

- Comma: GPS 없는 10분 터널(보조 유지), 켜진 채 재시작, 켜진 채 주행 종료, 시계 변경, `selfdriveState`만 단절.
- 수신 앱(`tests/test_direct_receiver.py`): `assist` 없는 옛 주행, 합계 불일치 값.
- HA: 90일 주행 기록 삭제 뒤 누적 유지, 늦은 주행 도착 시 기록되지 않은 거리 재계산, 분모 0 → `null`.
- HA "사용한 날": 보조 거리 0.9km인 날은 연속 기록이 끊기고, 1.0km인 날은 이어지는지. 날짜는 HA 시간대 기준인지.
- HA: `assist` 없는 주행은 집계에서 빠지고 "측정 안 됨"으로만 표시되는지.
- AGENTS.md 8절의 필수 회귀 검사 전체.

## 11. 배포 순서

수신 앱과 HA를 **먼저** 올리고 Comma를 마지막에 올린다.

1. **수신 앱**: `assist` 검증·보존·응답.
2. **HA 통합**: 영구 요약 저장·집계. 이 시점에는 "측정 안 됨"만 보인다.
3. **Comma 수집기**: 커밋·푸시 후 사용자가 `cd /data/openpilot && git pull --ff-only && sudo reboot`.
   기기 파일을 SSH/SCP로 고치지 않는다.

거꾸로 하면 HA가 받기 전에 수신 앱이 기록을 지워 값을 잃을 수 있다.
각 단계는 따로 검증하고 변경 기록(`CHANGELOG.md`, 수신 앱 CHANGELOG, openpilot 쪽 기록)에 남긴다.
pre-release·정식 발행은 사용자의 명시적 승인이 있을 때만 한다.

## 12. 사용자 결정 사항 (2026-11-05 확정)

1. **"사용한 날" 기준: 보조 거리 1km 이상.** (8-3의 4번)
2. **100m 미만 주행: 지금처럼 전송하지 않는다.** 그 거리는 "기록되지 않은 거리(추정)"에만 포함된다.
3. **과거 30초 간격 추정치: 숨긴다.** 통계는 Comma 업데이트 후 첫 주행부터 시작하고, 그 전 주행은 "측정 안 됨"이다.
   (한때 "보여 줌"으로 정했다가 같은 날 "숨김"으로 바꿈.)
4. **해제 위치·이유: 기록하지 않는다.** 나중에 추가하면 그 이전 주행에는 이 정보가 없다.

## 13. 이번 계획에서 하지 않는 것

- 화면(카드) 구현. 데이터가 쌓인 뒤 프리뷰부터 따로 진행한다.
- 기존 주행 거리 계산 방식 변경, 기존 텔레메트리 `enabled` 유효기간 변경.
- 1초 안의 전환까지 세는 별도 전환 수집기.
- 같은 주행 `assist`의 정정(`revision`).
- 과거 주행의 추정치(30초 간격 상태 기록 이용)와 rlog 재분석을 통한 보조 거리 복원.
