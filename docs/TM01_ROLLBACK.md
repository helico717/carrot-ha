# TM_01 실험 종료·원복 준비 — 2026-11-14

사용자가 연구 종료와 원복 준비를 요청했다. 기기 전체를 재설치하거나 과거 커밋으로 전체 저장소를 되돌리지 않고, 실험 변경만 제거한다. 원격 공조·도어 시험의 조사 문서와 결과는 보존한다.

## 변경 범위

- Comma: trial CLI·임대 판독·mode35·Classic-CAN 강제·시험 전후 큐 초기화 예외·전용 테스트/CI 제거. 수정했던 런타임 파일5개는 시험 전2f71f8b0d와 바이트 단위로 일치한다. 기존 정상 MEB mode34와 noOutput 정책은 그대로다.
- HA: 시험 버튼3개·결과 센서·실행 컨트롤러·button 플랫폼 등록 제거. 재시작 후 현재 차량의 정확한 unique ID4개만 정리하고, 다른 엔터티가 없고 다른 통합/설정 항목과 공유되지 않은 시험 자식 디바이스만 제거한다. 실제 도어 상태 센서·차량·Comma 디바이스는 보존한다.
- 영수증 인식 등 후속 변경은 보존한다. 연구 보고서와 Git 밖 시험 결과·기존 펌웨어 백업은 삭제하지 않는다. 결과 디렉터리나 lease 파일을 정리할 필요 없이 새 pandad는 시험 임대 자체를 읽지 않는다.

## 확인한 검증

- H7/F4 실제 펌웨어 컴파일·링크·서명 통과. 이 빌드 산출물은 기기에 복사하지 않는다.
- 실제 native 안전 정책: mode35 미지원(-1), noOutput의3bus×3payload 차단, 정상 MEB34 초기화 통과.
- HA 엔터티 마이그레이션9개/기존 WebSocket 터미널5개 통과. 신규 정리 검사는 다른 차량·다른 엔터티·공유 디바이스·다른 identifier 보존을 포함한다.
- 설치 후 실제 운행·Panda live signature 검증은 아직 하지 않았다. 로컬 빌드를 실차 설치 완료로 해석하지 않는다.

## 사용자 적용 순서

1. HA 직접 반영 완료가 확인된 후 사용자가 HA Core를 재시작한다. 시험 버튼과 결과 센서가 제거되며, 불필요한 빈 시험 디바이스가 정리된다. 직접 반영이 실패하면 그 사실을 별도 보고하며 HA 준비 완료라고 하지 않는다.
2. 차량에 접근할 수 있고 주차 상태일 때 Comma에서 다음 명령 또는 기존 Git Pull·기기 재부팅 버튼을 사용한다.

```sh
cd /data/openpilot && git pull --ff-only && sudo reboot
```

3. 정상 시작 과정에서 코드에 맞는 Panda 펌웨어를 빌드/서명 비교하고 필요하면 자동 갱신한다. 사용자가 별도 DFU 플래시를 먼저 할 필요는 없다. 처음 부팅은 빌드/기록 때문에 평소보다 오래 걸릴 수 있다.
4. 부팅 완료 후 Panda 연결 오류가 없는지와 평소 차량 인식·openpilot 시작을 확인한다. 오류가 있으면 전체 재설치부터 하지 않고 시작 로그와 firmware 서명 불일치 여부를 확인한다.

에이전트는 Comma Git Pull·재부팅·펌웨어 기록을 대신 실행하지 않는다. 일반 원복에 전체 재설치는 필요하지 않지만, 기록 중 장애가 발생하면 현장 Panda 복구가 필요할 가능성은 남는다. 기존 작동 펌웨어 백업이 있다는 사실은 자동 복구 성공 보장이 아니다.

## 발행·적용 기록

소스 커밋과 HA 파일 반영 결과는 CHANGELOG.md의 최신 종료 기록을 따른다. HACS 릴리즈·태그 발행은 하지 않는다. 사용자 재시작 전에는 실행 중 HA 메모리에 기존 버튼이 남을 수 있다. Comma도 사용자 업데이트·재부팅 전에는 시험 펌웨어가 남아 있다.
