# HA 주행 로그 이식 탐색 결과 및 구현 계획

작성·실서버 확인: 2026-10-14 13:06–13:10 KST. 상태: 구현 전 계획서.
이번 범위는 읽기 전용 환경 조사와 계획 작성이다. 운영 설정, HA 실행 코드,
Comma 코드, Worker/D1/KV를 변경하지 않았고 파일 시험 업로드도 실행하지 않았다.

## 1. 확정 요구사항

1. 기존 파라미터 카드가 표시되는 자리를 로그 조회 화면으로 교체한다.
   파라미터 기능의 통합 코드·서비스까지 삭제하는 작업으로 확대하지 않는다.
2. 당근웹 로그 화면의 기능을 이식한다. 목록·정렬·구간 선택·영상·리플레이,
   최근/선택 로그 전송, 전송 진행·취소·재개, 원본 다운로드와 선택 내보내기를
   기능별로 대조한다. 화면 녹화 등 기존 로그 메뉴의 하위 기능도 목록에 포함한다.
3. 첨부 Carrot Routes 분석 화면을 HA 보관본에서 직접 제공한다. 외부 로그 서버에
   전송하지 않아도 영상, 레이더 검증, 그래프, 구간 파일 정보를 볼 수 있어야 한다.
4. 지도 위 날짜 선택기로 날짜를 선택하면 보관 중인 로그의 모든 GPS 경로를 표시한다.
   경로 위치 선택으로 해당 주행·구간·재생 시점을 찾는다.
5. HA에는 실제 기록 시각이 최신인 로그부터 최대 5GB만 유지한다. 오래된 기록을
   우선 정리하고 보관 고정 예외는 두지 않는다. 업로드 순서는 보관 순서가 아니다.
6. 완성된 구간은 주행 중에도 즉시 전송하고 주차 후 누락분을 대조·보충한다.
7. 기존 Cloudflare 무료 플랜 사용을 침해할 가능성이 있으면 원본은 HA 직접 전송한다.
   현재 계획은 Worker/D1/KV 변경·원본 중계 없이 직접 전송을 기본으로 한다.
8. 기존 대시보드·차계부·파라미터·카메라·원격 터미널의 계약과 저장소를 보존한다.
   Comma 소스는 Git 배포만 사용한다. 원격 수동 파일 수정·재부팅은 수행하지 않는다.

## 3. 소스 재사용 조사

### 당근웹 로그 UI

openpilot의 `openpilot/selfdrive/carrot/web/src/features/logs/` 및 `features/replay/`
모듈을 기능별로 재사용한다. `server/features/dashcam/routes.py`의 기존 API가
목록, 파일, 업로드, 리플레이 입력 설명을 제공한다. 완성되지 않은 구간은 현재도
전송 대상으로 거부한다. `route_summary/worker.js`는 브라우저에서 압축 로그와
Cap'n Proto 이벤트를 해석한다. HA 설정 화면의 기존 `ha_bridge.js`는 설정 API만
지원하므로 로그용 브리지를 별도로 구현해야 한다. 파일·Web Worker 경로를 포함해
HA 정적 자산 경로 아래로 옮기고 전체 당근웹 앱을 함께 로드하지 않는다.

### 첨부 분석 화면

원본 위치는 openpilot의 `tools/carrot_route_vault/`이다. 단순 업로드 수신기인
`tools/carrot_upload_server/`와 구분한다.

- `viewer.py`: 주행/구간 페이지, 영상, 파일 목록 및 외부 도구 명령.
- `radar_view.js`: 레이더 화면과 영상·그래프 동기 조작.
- `radar.py`: 별도 Python 프로세스에서 분석, 준비 상태 응답, 결과 gzip 캐시.
- `radar/tools/radar_web_export.py`: `ProductionDPathSelector` 기반 재계산 결과.
- `build_bundle.py`, `Dockerfile.vault`: 커밋된 계산 코드·cereal/opendbc·네이티브
  모듈을 묶는 배포 방식. 의존성은 numpy, pycapnp, zstandard, ffmpeg 등이다.

재사용 시 반드시 유지할 의미:

- 기록된 Lead와 재계산된 Lead를 구분하고 계산 코드 버전을 표시한다.
- 센서 선택과 레이더 좌우 설정은 분석에만 적용하며 차량 설정을 쓰지 않는다.
- 기존 재계산 민감도 3, 기록된 EnableRadarTracks 정책과 좌우 보정 의미를 보존한다.
- qcamera 기록 시각으로 동기화한다. 정보가 없으면 독립 타임라인 상태를 표시한다.
- rlog 우선, qlog 대체 시 제한을 표시한다.
- Cabana/PlotJuggler/JotPluggler는 PC에서 실행하는 명령·API 연결을 제공한다.
  HA에서 해당 데스크톱 프로그램 자체를 실행하는 의미가 아니다.

기존 vault 전체 서버를 그대로 노출하지 않는다. 공용 share, 모델 다운로드,
자동 세션 발급과 서버의 10GiB 영상/2GiB 분석 캐시 기본값은 HA 정책에 맞게 제외·교체한다.

## 4. 권장 구성과 경계

```text
Comma: 완성 구간 발견 → 영속 전송 대기열 → 인증된 HTTPS 분할 업로드
                         ↓ 기존 테더링 인터넷
DuckDNS / 기존 Nginx Proxy Manager
                         ↓ HA 전용 수신 API
HA 로그 저장소 + 파일/GPS 색인 ── 제한된 분석 작업 ── 별도 분석 서비스
                         ↓ HA 인증된 조회·파일 API
기존 카드 위치: 로그 목록 / 날짜별 지도 / 리플레이 / 첨부 분석 화면
```

HA 모듈은 `custom_components/carrot_ha/driving_logs/`에 둔다. UI는 전용 로그 카드와
필요한 당근웹 모듈을 사용한다. 차계부 모듈과 DB에는 연결하지 않는다.
원본 저장소는 통합의 코드/Recorder/텔레메트리 archive 밖에 둔다.
HAOS의 `/media/carrot_ha/driving_logs/`를 후보로 하고, 통합과 분석 앱이 실제로
공유 접근 가능한지 확인 후 확정한다. 메타데이터는 해당 영역의 전용 SQLite로 관리한다.

레이더 재계산·ffmpeg는 HA Core 이벤트 루프와 분리한다. ARM64용 HA 앱(애드온)으로
최소 분석 서비스를 패키징하고, 내부 인증된 작업 API로 연결하는 방식을 우선한다.
앱 설치 없이 HACS만으로 동일 기능을 안정 제공할 수 있다는 주장은 하지 않는다.
앱 설치 방법, 재시작·복구, 로그 저장소 공유를 구현 산출물에 포함한다.
원본 업로드는 HA 수신 API에서 bounded streaming으로 처리하며 별도 앱까지 직접
외부 공개하지 않는다. 청크 크기로 HA HTTP 본문 제한과 프록시 제한을 회피한다.

원본·GPS·상세 분석 결과는 Cloudflare에 보내지 않는다. 업로드 주소·전용 자격증명
설정은 기존 장치 설정 배포 경로를 조사하여 한 번만 전달한다. 기존 Worker를 쓰는
경우에도 기존 설정 전달 계약 안의 변화인지 확인하고, 로그용 새 polling은 추가하지 않는다.
직접 로컬 초기 설정이 필요하면 사용자 설치 절차에 명시하고 SSH 코드 주입은 금지한다.

## 5. 최신 5GB 정책

표시와 계산을 일치시키기 위해 5GB=5,000,000,000 bytes를 계획 기본값으로 둔다.
5GiB로 바꾸려면 구현 전에 명시한다. 시스템 패키지·기존 차계부 DB는 대상 밖이다.
이 기능이 관리하는 원본, 색인, 썸네일, 분석 캐시, 미완료 수신 파일은 용량 예산에
포함한다. DB WAL 등 실제 사용량도 계측한다. 캐시보다 최신 원본을 우선한다.

- 원본 보관 기본 세트: 완성 구간의 qcamera+rlog. 추가 파일·화면 녹화는 동일 용량
  예산을 사용하며 지원 기능 표에서 원본 존재 여부를 표시한다.
- 장치·route·segment별 실제 기록 UTC 시작/종료 시각을 저장한다. route 문자열이나
  HA 도착 시각으로 신구를 결정하지 않는다. 시각 불명 로그는 자동 우선순위를 추측하지 않는다.
- 최신 구간부터 누적한 연속 보관 범위를 선택한다. 경계 구간이 남은 예산보다 크면
  그 구간과 더 오래된 구간은 제외한다. 작은 옛 구간으로 빈틈을 채우지 않는다.
- 파일을 중간 절단하지 않는다. 한 구간이 전체 제한보다 크면 보관 불가 상태를 표시한다.
- 새 수신 전에 크기 예약·오래된 구간 정리·디스크 여유 확인을 한다. 도중 데이터도
  예약에 포함하고 예상 크기 초과를 거부한다. 캐시 생성 역시 같은 예산을 사용한다.
- 재생/내보내기와 정리가 충돌하면 오래된 파일을 무기한 고정하지 않고 작업을 정리하거나
  취소한 뒤 회수한다. 파일 핸들까지 닫아 삭제 후 열린 파일의 숨은 디스크 사용을 방지한다.
- 보관 제외/삭제 목록과 보관 경계를 유지한다. 누락 대조가 정리한 옛 로그를 다시 받지 않게 한다.
- 지도에는 현재 보관 구간만 표시한다. 과거 원본을 삭제하면서 전체 GPS를 영구 유지하는
  별도 기록 기능은 이번 범위에 포함하지 않는다. 동일 주행의 앞부분이 없으면 부분 보관 표시.

## 6. 전송 프로토콜과 복구

제안 API는 `/api/carrot_ha/v1/driving_logs/` 아래로 제한한다.
장치 manifest 교환, upload 생성, 청크 PUT, 수신 offset 조회, commit, 상태 조회를 둔다.
브라우저는 HA 사용자 인증, 기기는 별도 장치 범위 업로드 토큰을 쓴다.
HA 관리자 장기 토큰을 Comma에 저장하지 않는다. 토큰 회전·폐기와 경로 검증을 구현한다.

1. Comma가 파일 잠금 해제/기존 완료 판정을 확인하고 길이·기록 시각을 manifest에 넣는다.
2. HA가 최신 보관 범위·기존 파일·용량 예약을 기준으로 필요한 파일만 요청한다.
3. 단일 동시 업로드, 초기 청크 후보 256KiB. 실제 HA와 프록시 제한을 측정해 확정한다.
4. 파일 offset과 upload ID를 영속화하고 ACK 다음 청크를 보낸다. offset 충돌은 서버 상태와 대조한다.
5. 수신 중 계산한 SHA-256/크기를 commit에서 검증하고 원자적 공개 후 완료 ACK를 보낸다.
   기기 해시는 전송 중 계산하여 불필요한 전체 파일 재읽기를 줄인다.
6. 연결 단절·HA 재시작·Comma 전원 차단 후 이어받는다. 지수 backoff와 jitter, 재시도
   상한/오류 분류를 둔다. source 삭제·변경·보관 제외는 계속 재시도하지 않는다.
7. 주행 중 완료 구간마다 전송한다. 주차 후 목록 비교로 누락·부분 파일을 보충한다.
8. 과거 backlog는 최신부터 전송하고 새 완료 구간이 뒤에 묻히지 않게 우선순위를 갱신한다.

기기 영속 대기열은 `/data/carrot_ha/driving_logs/` 등 Git 밖에 저장한다. 기존 loggerd
삭제 정책을 변경하거나 로그를 이중 복사해 무제한 보존하지 않는다. 원본이 먼저 삭제되면
복구 불가능한 누락으로 표시한다. 전송속도<생성속도이면 backlog가 생기는 사실을 표시한다.
CPU·열·I/O·메모리 실측 후 전송 한도와 pause 조건을 정한다. 설정 변경·실시간 제어와
같은 우선순위로 실행하지 않으며 주행 중 실제 검증 없이는 무부하라고 주장하지 않는다.

| 로그 목록 | 기존 시각적 구조, 날짜·정렬·펼침·다중 선택·구간 목록, 부분 보관/전송 상태 |
| 영상/리플레이 | Range seek, 구간 이동, 속도·재생 조작, 기록 시각 동기, 모바일 호환 |
| 전송 | 기존 Carrot/Toss 대상 정책·세션·완료 manifest·취소/재개를 보존; HA 보관본/기기 원본 출처 표시 |
| 내보내기 | 선택 구간 manifest+원본을 streaming ZIP 등으로 제공, 대형 임시 ZIP 중복 저장 방지 |
| 분석 | 영상+레이더, sensor/range/orientation, 트랙 선택, 기록/재계산 Lead, 거리·속도·가속도 그래프 |
| 외부 도구 | scope 제한 API_HOST/단기 읽기 자격, PC 명령 복사; 공개 무인증 원본 URL 금지 |
| 지도 | 상단 날짜 선택, HA 시간대의 날짜 범위→UTC 조회, 전체 해당 경로, 중첩 후보, 구간/시점 선택 |
| 화면 녹화 | 별도 파일 종류로 동기화·재생·다운로드, 최신 시각 기준 동일 예산 적용 |

지도 색인은 수신 완료 후 한 번 만들고 화면에서 반복 원본 해석하지 않는다. 다운샘플링
좌표에도 원본 시각·segment 참조를 보존한다. GPS 없음/불량/시간 공백은 표시하고 서로
떨어진 경로를 직선으로 연결하지 않는다. 데이터 조회는 HA 로컬만 사용한다.
지도 타일 제공자·사용 조건은 기존 지도 방식과 일치시키고 구현 시 별도 확인한다.

## 8. 단계별 실행 및 완료 조건

### A. 네트워크·의존성 검증

- 대상 프록시의 include와 HA body size/timeout 유효값 확인. 변경 필요성부터 입증.
- 테스트 수신 API 마련 후 작은 파일→청크 제한→중단 재개→실제 구간 전송 검증.
  현재 운영에 없는 API에 임의 PUT을 보내지 않는다.
- 차량 테더링 경로에서 TLS/인증/장시간 전송 확인. Mac VPN 성공으로 대체하지 않는다.
- ARM64 분석 이미지 빌드·실행, 실제 샘플의 기존 vault 결과와 frame/time/graph 비교.
- 생성 MB/min, 전송 MB/min, Comma CPU/열/I/O와 HA 응답 지연을 측정한다.

### B. 저장소·수신·전송 구현

- 전용 index, quota 예약, 최신 구간 경계, 삭제 이력, 회복 가능한 upload state 구현.
- 동일 청크/commit 중복, 재시작, 디스크 부족, hash mismatch, 원본 삭제, 시간 순서
  역전 도착과 한 구간 초과를 테스트한다. 동시 접근 중에도 총 예산을 초과하지 않는지 검증.
- Comma Git 관리 프로세스와 전송 대기열 연결. 기존 telemetry/param/terminal 주기를 보존.

### C. 기존 기능 완전 이식

- 당근웹 메뉴/버튼/API 전체 기능 표를 먼저 작성하고 모든 행을 테스트로 연결한다.
- 목록·영상·리플레이·전송·내보내기·화면 녹화를 이식한다. 미지원 항목을 숨겨 완료로
  보고하지 않는다. 보관되지 않은 원본은 기기 연결 여부와 복구 가능 상태를 명시한다.
- 기존 당근 서버 전송 정책과 일일 제한을 독립적으로 보존한다. HA 5GB 보관이 당근 서버
  전송 한도를 늘리는 것은 아니다.

### D. 분석·지도 및 회귀 검증

- 첨부 화면의 모든 조작과 기존 vault 계산 의미를 대조한다. 같은 로그·코드 버전·옵션의
  그래프와 트랙 비교, 영상 seek/time alignment, 손상·부분 로그·GPS 없음 검증.
- 다중 주행/중첩 경로/날짜 경계/타임존/보관 삭제 후 지도 일관성 검증.
- Chromium 비동기 갱신 후 후속 animation frame까지 스크롤·선택·지도 상태 보존 검증.
- 기존 필수 gates: dashboard-live-loading, dashboard-lazy-runtime, dashboard-view-state,
  test_cloud_live, test_incremental_sync, test_history_cache, Worker incremental/benchmark,
  Comma test_param_polling 및 관련 daemon suite. auth/isolation·차계부·trip/charge·카메라
  driving interlock·terminal 회귀도 보존. 기존 실패는 신규 실패와 구분해 기록.

### E. 배포·운영 확인

- HA 변경은 0.8.x manifest/태그 일치, 릴리즈 노트·GitHub Release·Actions 검증.
- Comma 변경은 `carrot-wip-model_selector-ha` 커밋·푸시 및 원격 SHA 확인.
- 분석 앱은 커밋 기반 ARM64 패키지·설치 안내·버전·rollback 제공. upstream 계산 소스는
  고정 버전과 fingerprint로 관리하고 실행 중 원격 코드를 받아 실행하지 않는다.
- Worker/D1/KV 변경·배포는 현재 계획상 필요 없다. 필요가 새로 생기면 근거와 범위를 재평가.
- 사용자는 앱/HACS 설치·HA 재시작과 Comma `git pull --ff-only`·재부팅을 수행한다.
- 실제 주행+주차+전원 차단/재연결, 5GB 회전과 24시간 기존 서비스 지연/계정 사용량을
  확인한다. 로컬 테스트·발행만으로 실차 운영 완료를 선언하지 않는다.

## 9. 결정 및 미확인 항목

기능 구현은 가능하며 재사용할 화면과 분석 엔진이 존재한다. 직접 HTTPS 경로와 저장
여유도 확인했다. 우선 구성은 완성 구간 즉시 전송+주차 후 누락 보충, 최신 5GB 회전,
HA 로컬 조회, 별도 ARM64 분석 앱이다. SSH 접근 성공은 구현·실차 검증 성공이 아니다.

남은 핵심 확인: 프록시 include/HA 유효 제한, 차량 테더링 전송 성능, ARM64 네이티브
빌드·분석 비용, 공유 media 경로, 정확한 메뉴별 기능 대조와 실제 영상 브라우저 호환성.
HA Supervisor CLI 권한 오류는 설치 단계 전에 정상 접근 방법을 확인하되 토큰을 임의로
수정하지 않는다. 이번 계획서 작성으로 해당 검증들을 실행했다고 주장하지 않는다.
