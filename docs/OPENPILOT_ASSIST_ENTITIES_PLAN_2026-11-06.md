# 오픈파일럿 사용 통계 — HA 엔터티 계획서 (2026-11-06)

상태: **계획 단계. 코드 변경 없음.** 사용자 승인 후 구현한다.
관련: [백엔드 계획서](OPENPILOT_ASSIST_STATS_PLAN_2026-11-05.md), 구현된 집계 `custom_components/carrot_ha/assist_stats.py`.

## 1. 원칙 — 엔터티는 늘리지 않고, 의미 있는 값만

지금 Carrot 엔터티는 **86개**다(활성 센서 52개: 일반 26, 진단 26 / 비활성 센서 16). 그래서 이번에는 다음을 지킨다.

1. **새 엔터티는 2개만 만든다.** 통계마다 엔터티를 하나씩 만들지 않는다.
2. **엔터티 하나 = 대표값 하나.** 나머지 세부 숫자는 그 엔터티의 **속성**에 묶는다(기존 "오늘의 주행 요약"과 같은 방식).
3. **주행 1건의 통계는 새 엔터티 없이** 기존 "최근 주행 결과" 엔터티의 속성에 더한다.
4. 일별·월별 목록처럼 긴 데이터는 엔터티에 넣지 않는다. HA 기록(recorder) DB가 불어나지 않게, 화면은 조회 API(`carrot_ha/assist/summary`)로 받는다.

## 2. 새로 추가하는 엔터티 (2개)

엔터티 ID는 기존 규칙(기기 이름 `ID.4` + 영문 키)에 따라 아래처럼 만들어진다.
실제로 만들어진 ID가 다르면 구현 단계에서 바로잡고 보고한다.

### ① 오픈파일럿 사용률

| 항목 | 값 |
|---|---|
| 엔터티 ID | `sensor.id_4_openpilot_assist_ratio` |
| 표시 이름 | **오픈파일럿 사용률** |
| 상태값 | 통계 시작 이후 누적 사용률. 예: `97.9` |
| 단위 | `%` (소수 1자리) |
| 아이콘 | `mdi:steering` |
| 종류 | 일반 센서, 기본 활성, `state_class: measurement` |
| 값이 없을 때 | 첫 측정 주행 전, 또는 보조·수동 거리가 모두 0이면 `알 수 없음` |

계산식: 사용률 = 보조 거리 ÷ (보조 거리 + 수동 거리). 상태 모름 거리는 분모에 넣지 않는다.

**속성** (테슬라 통계 화면의 숫자들을 여기에 모은다)

| 속성 이름 | 뜻 | 단위 |
|---|---|---|
| `since` | 통계 시작 시각 | 시각 |
| `assist_km` | 누적 오픈파일럿 주행거리 | km |
| `manual_km` | 누적 수동 주행거리 | km |
| `unknown_km` | 누적 상태 모름 거리 | km |
| `month_ratio` | 이번 달 사용률 | % |
| `month_assist_km` | 이번 달 오픈파일럿 주행거리 | km |
| `longest_streak_km` | 최장 연속 오픈파일럿 주행거리 | km |
| `longest_streak_at` | 최장 기록 시작 시각 | 시각 |
| `current_streak_days` | 현재 연속 사용 일수 (하루 1km 이상) | 일 |
| `best_streak_days` | 최장 연속 사용 일수 | 일 |
| `active_days` | 사용한 날 수 | 일 |
| `measured_trips` | 통계가 측정된 주행 수 | 회 |
| `disengagements` | 누적 해제 횟수 (1초 표본 기준) | 회 |
| `unrecorded_estimate_km` | 기록되지 않은 거리 (주행거리계 기준 추정) | km |

### ② 오픈파일럿 누적 주행거리

| 항목 | 값 |
|---|---|
| 엔터티 ID | `sensor.id_4_openpilot_assist_distance` |
| 표시 이름 | **오픈파일럿 누적 주행거리** |
| 상태값 | 통계 시작 이후 오픈파일럿으로 달린 거리. 예: `303.4` |
| 단위 | `km` (소수 1자리), `device_class: distance` |
| 아이콘 | `mdi:map-marker-path` |
| 종류 | 일반 센서, 기본 활성, `state_class: total_increasing` |

`total_increasing`이라서 HA가 장기 통계를 자동으로 만든다. 그래서 HA 기본 **통계 그래프 카드**에서 일·주·월별 막대그래프(테슬라 화면의 월별 막대)를 별도 코드 없이 바로 볼 수 있다.
이 값은 줄어들지 않는다. 같은 주행이 다시 와도 처음 받은 값을 지키기 때문이다.

**속성** (보조 종류별 내역)

| 속성 이름 | 뜻 | 단위 |
|---|---|---|
| `lateral_only_km` | 조향만 켜진 거리 | km |
| `longitudinal_only_km` | 가감속만 켜진 거리 | km |
| `both_km` | 조향·가감속 둘 다 켜진 거리 | km |
| `system_enabled_km` | 시스템 활성(`enabled`) 기준 거리 (참고용) | km |
| `today_assist_km` | 오늘 오픈파일럿 주행거리 | km |

## 3. 기존 엔터티에 속성만 추가

### `sensor.id_4_last_trip` (최근 주행 결과) — 엔터티는 그대로

| 추가 속성 이름 | 뜻 | 단위 |
|---|---|---|
| `assist_ratio` | 이 주행의 오픈파일럿 사용률 | % |
| `assist_km` | 이 주행의 오픈파일럿 주행거리 | km |
| `manual_km` | 이 주행의 수동 주행거리 | km |
| `assist_longest_streak_km` | 이 주행의 최장 연속 거리 | km |
| `assist_disengagements` | 이 주행의 해제 횟수 | 회 |

통계가 없는 주행(업데이트 전 주행 등)이면 이 속성들은 `null`이다.

## 4. 만들지 않는 것과 이유

| 후보 | 이유 |
|---|---|
| 수동 거리·상태 모름 거리 엔터티 | 사용률 속성으로 충분하다 |
| 조향만·가감속만·둘 다 엔터티 3개 | 분석용 세부값이다. 누적 주행거리 속성으로 둔다 |
| 연속 사용 일수·최장 연속 거리 엔터티 | 사용률 속성으로 충분하다. 화면에서 바로 꺼내 쓸 수 있다 |
| 이번 달·오늘 통계 엔터티 | 기간 값은 속성과 HA 장기 통계로 볼 수 있다 |
| 켜짐·해제 횟수 엔터티 | 1초 표본 기준이라 대표값으로 쓰기에 적합하지 않다 |
| 일별·월별 목록 속성 | 기록 DB가 커진다. 조회 API로 제공한다 |

## 5. 갱신 방식 (성능 계약 준수)

- 엔터티는 수신 앱에 따로 묻지 않는다. HA가 이미 계산하는 공유 집계(`assist_summary`, 캐시)를 읽기만 한다(AGENTS.md 8절).
- 새 주행이 저장돼 통계가 바뀔 때 갱신한다. 날짜가 바뀌면 연속 일수와 "오늘" 값이 달라지므로, 자정에 한 번 더 갱신한다.
- 속성은 숫자만 둔다(엔터티 하나에 15개 안팎). 주행이 없으면 값이 바뀌지 않아 기록 DB에 새 행이 쌓이지 않는다.

## 6. 구현·검증 계획 (승인 후)

1. `sensors_v3.py`에 두 엔터티 추가, `LastTripSensor` 속성 추가. 런타임에 집계 결과를 보관하고, 통계 변경 시·자정에 갱신.
2. 테스트: 첫 측정 전 `알 수 없음`, 사용률·분모 규칙, `total_increasing` 값이 줄지 않는지, 최근 주행 속성의 `null` 처리.
3. 커밋·푸시 → HA SSH 직접 반영(백업·해시 검증) → 사용자 HA 재시작.
4. 재시작 후 실제 엔터티 ID 두 개가 위 표와 같은지 레지스트리에서 확인하고 보고한다.
5. 버전 상승·릴리즈는 하지 않는다(2026-10-21 정책).

## 7. 정해 주실 것

1. 엔터티 이름 두 개("오픈파일럿 사용률", "오픈파일럿 누적 주행거리")가 괜찮은지.
2. `unrecorded_estimate_km`(기록되지 않은 거리 추정)를 속성에 넣을지. 정확도가 1km 단위라 혼동될 수 있다.
