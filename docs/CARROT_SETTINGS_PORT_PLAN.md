# 당근 웹 파라미터 설정 화면 HA 이식 계획

## 목표와 범위

사용자가 제공한 당근 웹 설정 화면의 레이아웃, 탐색, 파라미터 편집 및 클릭 시 상세설명을 HA에서 재현한다. 파라미터 목록은 차량에 설치된 CarrotPilot의 카탈로그를 기준으로 추가·삭제·변경을 자동 반영한다. 185개는 현재 관측값이며 고정 요구사항이 아니다. 이번 문서는 분석과 구현 계획이며 배포 또는 구현 완료를 뜻하지 않는다.

설정 화면을 대상으로 한다. Drive, Tools, Logs, Terminal 전체 기능 이식은 이 범위에 포함하지 않는다. 설정 화면에서 보이는 인기값 등 부가 기능은 의존 API를 조사하고 지원 여부를 명시한다. 임의 데이터로 채우거나 동작하지 않는 버튼을 남기지 않는다.

## 확인한 사실과 남은 확인

- 운영 HA 브라우저에서 카드 등록 성공, settings 응답 ok=true, 값 185개를 사용자가 확인했다. 기본 조회 경로는 작동한다.
- 현재 HA 카드는 원본 컴포넌트/CSS를 사용하지 않고 자체 HTML/CSS로 재작성되어 있다. 카테고리 버튼, 스테퍼, 아코디언은 원본 화면과 다르다.
- 현재 상세설명은 catalog 항목의 descr/edescr만 표시한다. 원본의 Wiki 상세설명 연동이 없다.
- 로컬 openpilot 참조 소스에는 settings 전용 탐색/렌더링/선택 대화상자/CSS/문서 로더가 있다. published_documentation.js는 공식 Wiki Settings-Catalog.json과 언어별 문서를 사용하고 해시·스키마를 검증한다.
- 원본 카테고리의 groups → sections → items 구조를 평면 필터로 축약해 탐색 구조가 소실됐다.
- param_sync.py는 기본 180초 주기로 catalog와 values를 업로드한다. 현재 카드의 4초 폴링은 대기 명령 상태에만 해당하며 카탈로그 주기 갱신이 아니다.
- 현재 변경 상태는 이름 단위 Set으로 관리하고 Worker 상태 조회는 최근 20개를 반환한다. 동일 이름 연속 변경, 오래된 대기 명령, 실패 처리가 충분하지 않다.
- 원본 참조 checkout은 helico717/openpilot 포크이며 upstream은 ajouatom/openpilot이다. 조사 당시 HEAD는 bdecdb4351ff4f7ca5c75d63431d21e7ada87bc3. 이 코드가 사용자의 차량 및 스크린샷 버전과 동일하다고 확정할 수 없다.

## 원인

요청을 '원본 설정 화면 이식'이 아닌 '동일 파라미터를 다루는 새 카드 제작'으로 구현했다. 데이터 개수와 API 성공을 검증했지만 원본과 화면/행동을 비교하는 인수 조건이 없었다. 상세설명과 부가 API 의존성을 분석하지 않고 스냅샷만 연결했다. 이전 입력 버그 수정은 이 구조적 차이를 해결하지 못한다.

## 구현 단계

### 1. 기준 버전 및 기능 목록 확정

차량의 브랜치/커밋과 원본 설정 화면 자산 버전을 확인한다. 공식 upstream과 로컬 포크의 설정 관련 차이를 비교하고 이식 기준 커밋을 고정한다. 카테고리 탐색, 뒤로가기, 검색, 토글, 값 편집, 단위 변환, 기본값, 상세설명, 인기값, 모바일 메뉴의 실제 동작과 API를 표로 정리한다. 스크린샷과 데스크톱/모바일 기준 화면을 확보한다.

### 2. 원본 UI를 재사용하는 HA 호스트 구성

원본 설정용 HTML 구조, CSS/디자인 토큰, 아이콘, 렌더러와 편집 로직을 가능한 한 그대로 가져온다. 기존 자체 카드 UI를 계속 확장하지 않는다. 원본 전역 document/window 의존성을 조사하고 전용 iframe 문서에서 실행하는 방식을 우선 검증한다. iframe 자산은 HA에서 제공하며 차량의 :7000 주소를 직접 임베드하지 않는다.

바깥 carrot-params-card는 장치 선택과 HA 인증 호출을 담당한다. 내부 설정 UI는 구조화된 메시지로 조회/변경을 요청한다. 메시지는 정확한 origin, source, 요청 ID, 허용 작업 목록을 검사한다. HA/Worker 토큰을 iframe이나 localStorage로 전달하지 않는다. 번들 자산과 메시지 연결이 HA CSP 및 모바일 앱 WebView에서 동작하는지 먼저 검증한다. iframe 부적합 시 DOM root를 주입할 수 있도록 원본 모듈을 조정한 Shadow DOM 호스트로 전환한다.

데스크톱은 원본 카테고리 사이드바와 우측 설정 화면을 보존하고 HA의 넓은 전용 뷰를 사용한다. 모바일은 원본 반응형 메뉴를 재사용한다. 출처와 라이선스를 보존하고 가져온 파일/커밋을 기록한다.

### 3. 통신 어댑터와 상세설명 연결

원본 snapshot 요청을 HA settings API로, 파라미터 변경 요청을 HA param_set 및 Worker queue로 연결한다. 원본이 기대하는 응답 구조는 어댑터에서 변환한다. 화면에 표시한 요청값과 차량이 확인한 적용값을 구분한다.

파라미터 클릭 시 원본 published documentation 로더 및 렌더러를 연결한다. 파라미터 키/언어로 공식 Wiki 인덱스의 문서를 찾고 캐시·스키마·해시 검증 및 안전한 문서 렌더링을 유지한다. 네트워크 제약이 있으면 고정된 공식 문서 경로만 HA에서 프록시한다. 임의 URL 프록시는 만들지 않는다. 문서 없음, 구버전 의미 불일치, 언어 대체, 로드 실패를 표시하고 catalog의 짧은 설명을 대체 정보로 제공한다.

인기값 등은 snapshot 이외 API의 데이터를 실제로 전달해야 한다. 해당 기능을 제공하는 장치에서 collector/Worker/HA를 통해 전달하고, 지원하지 않으면 원본의 비지원/빈 상태를 표시한다.

### 4. 추가·삭제·변경 자동 반영

차량의 실제 snapshot을 유일한 파라미터 목록 기준으로 삼는다. GitHub 최신 목록을 차량 목록 대신 사용하지 않는다. 카탈로그 전체 교체와 버전/hash, 수집 시각, 기기 소스 버전을 전송한다. 초기 로드, 화면 재진입, 표시 중 주기 조회로 변경을 감지한다. 기존 180초 업로드 주기에 HA 갱신 주기가 더해지는 지연을 문서화한다.

새 파라미터는 메뉴와 설명 연결까지 자동 생성한다. 삭제된 파라미터는 목록/검색/선택 상태에서 제거한다. 이름이 같아도 범위·기본값·단위·설명·카테고리 변경을 반영한다. 미완성 스냅샷이나 통신 실패를 정상적인 빈 카탈로그로 취급하지 않는다. 완전한 빈 스냅샷은 별도로 유효성을 판별해 이전 항목을 제거한다. 현재 검색/스크롤/한글 조합 상태를 보존하며 편집 중 메타데이터가 바뀌면 저장 전 다시 검증한다.

일반 카탈로그 변경은 HA 재배포 없이 반영한다. 새 스키마 또는 새 종류의 전용 UI 컨트롤이 생기면 어댑터/화면 업데이트가 필요할 수 있다. 파라미터 자동 반영과 upstream UI 코드 자동 업데이트를 구분한다.

### 5. 변경 적용 상태의 신뢰성

요청 ID로 대기/적용/실패/만료를 추적하고 실제 재조회 값으로 적용을 확인한다. 최근 20개 제한 때문에 상태가 누락되지 않도록 ID별 조회 또는 활성 대기 조회를 제공한다. 삭제된 파라미터의 오래된 요청, 범위가 바뀐 요청은 차량의 최신 정의로 검증하고 거절 이유를 돌려준다. 원본 서버의 검증과 적용 정책을 우회하지 않는다. 재전송의 중복 적용을 방지한다.

### 6. 검증 및 배포

동일 카탈로그/언어/뷰포트에서 원본과 HA 화면을 나란히 비교한다. 메뉴 순서, 크기, 간격, 색상, 값 편집과 설명 열기 행동을 검증한다. 한글 연속 입력·조합·붙여넣기·커서 이동을 실제 브라우저에서 확인한다. mock 기기로 추가/삭제/메타데이터 변경, 문서 없음, 통신 실패, 명령 지연/실패를 검증한다. 사용자가 선택한 변경에 대해서만 실제 차량 적용을 검증하고 임의 튜닝값은 전송하지 않는다.

collector/Worker/HA 변경을 구버전 호환 순서로 배포하고 필요시 D1 migration, 프런트 버전 갱신, 롤백 절차를 포함한다.

## 완료 조건

1. 사용자 기준 당근 웹 설정 화면의 탐색 구조와 시각 표현 및 편집 동작을 HA에서 재현한다.
2. 파라미터 클릭 시 동일 키의 상세 문서가 표시된다. 짧은 descr만 펼치는 것으로 완료 처리하지 않는다.
3. 차량 카탈로그의 추가·삭제·수정이 HA 재배포 없이 다음 정상 동기화 후 반영된다.
4. LTE 환경에서 조회/변경/차량 적용 확인을 끝까지 확인한다.
5. 원본과 달라야 하는 원격 대기/오프라인 표시 및 미지원 부가 기능은 명확히 표시한다.
6. 실제 브라우저에서 한글 입력과 모바일 조작이 정상이다.
