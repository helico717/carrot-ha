# 귀가 원시 CAN의 추가 모니터링 후보 — 2026-10-05

## 범위와 방법

이번 분석은 beta.7 설치 전 귀가 로그의 기존 로컬 사본을 재사용했다. 새 설치 후 로그를
다운로드하거나 HA/Comma의 실행 코드를 바꾸지 않았다. 원본 범위·시계·공백은
[충전 분석](raw-can-charge-analysis-2026-10-05.md)을 따른다.

배치별 첫 프레임으로 후보를 선별한 뒤 bus1의 선택된 9개 ID 전체 **2,143,912 프레임**을
검사했다. 4,506개 gzip 파일을 모두 읽었으며, 전체 수집은 79,494,733 프레임이다.
DC 구간은 기존 원시 모드 전이 22:29:38.486–22:42:27.168 KST를 사용했다.
주행 분류는 배치 컨텍스트 driving을 사용하므로 경계 정밀도는 프레임보다 낮다.
TAR 순서를 시간 순서로 가정하지 않고 first/last는 각 프레임의 anchor 변환 시각으로 비교했다.

신호 정의는 로컬 `openpilot/opendbc_repo/opendbc/dbc/vw_meb.dbc`를 사용했다.
파일 SHA256: `2abb7f12b1ba33bb2704b4d56075de91eeffef74a4712e7fbbd5984e568f052e`.
DBC 정의가 있다는 사실만으로 차량별 의미·배율·물리 정확도를 확정하지 않는다.
Init/Fehler 원시 코드는 수치로 표시하지 않고 따로 집계했다. 모든 아래 bit 정의는 little-endian이다.

재현 스크립트: [tools/analyze_can_monitoring.py](../tools/analyze_can_monitoring.py).
입력은 기존 gzip JSON을 담은 TAR이며, 출력에는 범위·원시 코드 분포·예시·분 단위 집계가 있다.
원본·인증정보를 저장소에 넣지 않는다. 로컬 결과는 `/private/tmp/carrot-can-analysis/monitor-full.json`.

부하 차이가 있으므로 수치 차이를 모두 공조/손실로 배분하지 않는다.

## 쓸 수 없거나 검증이 더 필요한 항목

- `0x5AC.HVEM_IstStrom_HVVerbraucher`는 **135,587건 전부 raw 4094=Init**.
  배율로 계산하면 204.7A처럼 보이지만 실측 전류가 아니다.
- `0xB8.EM1_IstStrom`은 유효 프레임 모두 raw 1023=0A, 초기화 13건이다.
  주행·회생 중에도 0이라 현재 정의로 유용한 전류 측정값이 아니다.
- `0x365.BEM_HYB_DC_uSollLV`는 전체 271,170건 모두 **14.3V 요청값**이다.
  `uMinLV`는 모두 raw 254=Init이다. 14.3V를 실제 12V 배터리 전압이나 SOC로 표시하면 안 된다.
- `0x5A2.BMS_Soll_SOC_HiRes`는 27,078건 모두 0이다. 현재 로그로 목표 충전 SOC를 알 수 없다.
- `0x5CD.DC_IstModus_02`는 27,169건 모두 0이며 온도 제한 bit도 모두 0이다.
  온도가 변하는 사실을 이 모드가 DC-DC 실제 작동을 판별한다는 근거로 확대하지 않는다.
- `0x569.PTC_ON` 후보는 28,600건 모두 0이다. 이 로그만으로 PTC/배터리 히터 상태를 검증할 수 없다.
- 고전압 전압 후보 두 개는 주행·충전의 범위가 서로 다르며 하나에는 818.8V 값도 등장한다.
  `Battery_Voltage` 주행 396.4~462.0V/DC 345.4~419.6V,
  `Battery_Voltage_02` 주행 375.6~377.76V/DC 296.64~378.24V.
  어느 필드가 어떤 전압인지 독립 계측과 비교하기 전에는 새 확정 센서나 SOH 근거로 채택하지 않는다.
- **12V SOC, 배터리 팩 온도, 셀별 전압/편차, SOH**는 이번 조사에서 검증 가능한 수신 신호를
  확보하지 못했다. 모든 미해석 메시지에 없다는 증명은 아니다. 기존 UDS 목록은 별도의 진단 질의 자료다.

## 원시 예시와 다음 검증

- 0x5AC `fe8f082fb9230840`: 공조 요청 raw47→2,350W, 기타 부하 raw17→850W,
  소비 전류 raw4094→Init. 같은 프레임의 일부만 유효하므로 메시지 전체를 유효/무효로 묶지 않는다.
- 0x5CD `8a410800000b0039`: 온도 raw57→17°C.
- 0x5A2 `ad8400ea11000000`: 용량 raw980→196.0Ah.
- 0x365 `b9040000000f94fe`: 저전압 요청 raw37→14.3V, 최저전압 raw254→Init.

다음 우선순위는 구동/회생 전력 후보의 배율·부호를 반복 주행으로 검증하고,
공조 켜기/끄기와 설정 변화가 공조 전력 요청에 대응하는지 비교하는 것이다.
DC-DC 온도와 HV 활성은 수신 상태 표시·장기 추세 후보로 남긴다.
이번 변경은 분석·문서·재현 도구이며 새 엔터티나 수집기 실행 코드를 발행하지 않는다.
