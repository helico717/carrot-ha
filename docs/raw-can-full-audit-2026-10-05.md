## 더 효율적인 수신·보고 방법

1. **원시 기록은 그대로 전량 보존하고, 엔터티 수신과 업로드 주기를 구분한다.** 현재 주요
   CANParser는30초마다 다시 만들고4초 읽은 뒤26초 쉰다. optional parser와 socket은 재사용한다.
   저우선순위의 지속 수신/최신값 캐시로 parser를 재사용하고, 실제 프레임 시각과 전이만 보관하면
   상태 전이를 더 빨리 잡고 반복 초기화 비용을 줄일 수 있다. Comma 실기 CPU/큐 측정 없이 이점이나
   무영향을 보증하지 않는다. 최신 상태의 전송은 기존 상한·공유 coordinator를 유지한다.
2. **보고할 값에는 출처·단위·측정시각·유효성·추정 여부를 함께 둔다.** BMS mode, 요청 mode,
   측정 전류, 허용 전류를 별도 값으로 보존한다. 수신 실패 시 마지막값을 새 측정처럼 갱신하지 않는다.
3. **무효 코드 필터는 개별 신호 단위로 둔다.** 문·잠금의 유효0을 보존하면서 raw14 내기순환,
   온도raw254, 최대값raw8190 등을 unknown으로 구분한다. 모든 메시지 전체를 무효로 만들지 않는다.
4. **원시 저장의 무손실 binary 형식**은 벤치마크의 주행/DC/주차 3개 배치에서 현재JSON+gzip1보다
   **25.2% / 29.9% / 31.5% 작은 파일**을 만들었다. 3개 모두 프레임 round-trip 일치.
   Mac에서 압축만 측정했고 포장·네트워크·Comma CPU는 제외했다. schema/ACK/구버전 호환이 필요한
   별도 개선 후보이다. 현20GB 정책·원시 전량 수집은 변경하지 않았다.
5. gzip6으로 단순 변경해도 약21~26% 줄지만 이 샘플에서는 압축 시간이 약4배 늘었다.
   실기 영향 확인 전 압축단계를 올리거나 프레임을 버리는 최적화는 채택하지 않는다.
