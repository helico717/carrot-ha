# 주행 로그 작업 지침

이 지침은 당근웹 주행 로그의 HA 이식, Comma 동기화, 로그 저장·조회·영상·리플레이,
레이더 분석·GPS 지도·외부 전송·내보내기와 해당 테스트·문서·배포 작업에 적용한다.

## 필수 변경 기록

- 작업을 시작할 때 이 파일과 `driving-logs/CHANGELOG.md`를 읽는다.
- 모든 관련 작업·커밋을 `driving-logs/CHANGELOG.md`에 즉시 기록한다. 기능·버그·UI·
  테스트·문서·지침·배포·롤백과 조사 결과도 포함한다.
- 각 항목은 날짜, 변경 내용, 이유, 관련 파일/저장소, 검증 결과, 배포 상태와 미확인
  사항을 포함한다. 커밋·원격 반영·HA 파일 반영·HA 재시작·실차 설치를 구분한다.
- 미완료 검증을 통과로 보고하지 않는다. 실패·제약·후속 작업도 기록한다.
- 커밋 전에 실제 diff와 대조해 누락을 확인하고, 이후 배포 결과를 다시 추가한다.

## 경계와 배포

- 관리 문서: `driving-logs/`. 계획서: `docs/driving-log-ha-implementation-plan-2026-10-14.md`.
- HA 실행 코드: `custom_components/carrot_ha/driving_logs/`, 로그 카드와 `frontend/carrot_logs/`.
  기존 카드·통합 등록부에 연결하는 변경도 이 지침을 따른다.
- Comma 실행 코드: openpilot `openpilot/selfdrive/carrot/ha/driving_logs.py` 및 연결부.
  Git 커밋·푸시로만 배포하고 SSH/SCP로 기기 파일을 수정하지 않는다.
- 차계부·텔레메트리 DB를 로그 저장소로 사용하지 않는다. 기존 Cloudflare polling을
  증폭하지 않는다. 파일 원본은 HA 직접 전송을 기본으로 한다.
- 사용자는 최신 로그만 최대 5GB 보관을 요청했다. 오래된 로그 고정 예외를 추가하지 않는다.
- 2026-10-14 사용자는 이번 단계의 **HA SSH 직접 반영·검증**을 명시적으로 요청했고,
  다듬은 뒤 pre-release를 발행하겠다고 했다. 현재 작업은 버전 상승·태그·Release 없이
  진행한다. 직접 반영 시 필요한 파일만 백업·동기화·해시 검증한다.
- HA/Comma 재시작·기기 Git Pull과 카드/리소스 변경은 사용자가 실행할 명령과 절차를
  제공한다. 운영 적용과 실차 검증이 끝나지 않았으면 그 상태를 정확히 보고한다.
- 토큰·개인키·원본 GPS/로그를 문서·커밋·출력에 포함하지 않는다.
