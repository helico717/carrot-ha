# 차계부 작업 지침

## 문서 언어

작성·수정하는 문서는 한국어 또는 영어로만 작성한다. 다른 언어가 우발적으로 섞이면
커밋 전에 검색해 수정한다. 코드 식별자·단위 기호·의도된 제품 번역은 언어 혼입과
구분한다. 참고 원문을 수정할 때는 수정 이유와 현재 해시를 기록해 출처를 보존한다.

## 사용자 지정 개발·배포 정책 — 2026-10-06

구체적인 커밋·푸시·SSH 반영·검증·릴리즈 절차와 현재 인계 상태는
[deployment.md](deployment.md)를 먼저 읽는다. Antigravity 등 다른 개발 에이전트에도 적용한다.

- 기존 v0.8.13은 GitHub pre-release로 유지한다. 태그를 덮어쓰지 않는다.
- 앞으로 수정마다 검증·커밋·main 푸시하고, 디버깅 중에는 새 릴리즈를 발행하지 않는다.
- 테스트 코드는 사용자 지정 SSH 직접 동기화 경로로 HA에 반영한다. 기존 코드 백업과
  배포 커밋·파일 해시를 확인하고 DB·사진·HA 설정은 동기화 대상에서 제외한다.
  Python 변경 적용을 위한 HA 재시작은 사용자가 수행한다.
- 버그 수정 완료 후 새 0.8.x-beta.N pre-release를 발행한다. 실사용 검증을 통과한
  뒤에만 정식 0.8.x 릴리즈를 발행한다. 로컬 테스트 통과만으로 정식 발행하지 않는다.
- 이 차계부 작업에는 사용자가 지정한 위 정책이 루트의 릴리즈 기본 정책보다 우선한다.
- HACS 업데이트·재다운로드가 직접 배포한 개발 코드를 덮어쓸 수 있으므로 테스트 중
  배포 커밋을 확인하고 두 경로를 혼용하지 않는다.

## 모든 변경사항의 changelog 기록 — 사용자 지정 (2026-10-06)

- 각 차계부 커밋에 `CHANGELOG.md` 항목을 함께 포함한다. 기능·버그·UI·DB·API·
  테스트·문서·지침·배포 정책·제거·복구 등 모든 변경사항을 빠짐없이 기록한다.
- 항목에는 날짜, 커밋 제목, 변경 내용과 이유, 관련 파일, 검증 결과, 배포 및 실제
  적용 상태, 알려진 제한을 남긴다. 자기 커밋 해시는 생성 전 알 수 없으므로 제목으로
  식별하고 다음 기록 또는 릴리즈 준비 때 확정 해시를 연결한다. 해시만 기록하지 않는다.
- pre-release 준비 시 이전 pre-release 이후 변경과 이번 개발 주기의 누적 변경을
  명시한다. 정식 릴리즈는 **직전 정식 릴리즈 이후 전체 변경**을 정리해 중간 베타에서
  소개된 수정도 빠뜨리지 않는다. 각 릴리즈의 기준 태그와 대상 커밋을 기록한다.
- `git log`와 실제 diff를 CHANGELOG.md에 대조해 누락을 보완하고,
  `.github/release-notes/<tag>.md`에 해당 범위의 모든 변경을 옮긴다. 관련 변경을
  묶어 설명할 수 있지만 항목 자체를 생략하지 않는다. GitHub 자동 노트만으로 대체하지 않는다.
- 발행 후 GitHub Release 본문·Actions 성공·pre-release 여부를 확인한다. HACS에
  노출되는 릴리즈 노트에도 변경 내용이 포함돼야 한다. 변경 기록 누락은 완료로 보고하지 않는다.
- 개인 기록·사진·위치·식별자·토큰은 변경 기록과 공개 릴리즈 노트에도 넣지 않는다.

루트 AGENTS.md와 함께 읽는다. 문서·SQL·참고 자료는 이 폴더에서 관리하고,
향후 실행 코드는 `custom_components/carrot_ha/vehicle_journal/`에 둔다.
해당 실행 코드 및 기존 통합 연결부 작업에도 이 지침을 적용한다.

- HA 내부 저장·계산·조회가 원칙이다. 차계부 때문에 Cloudflare/Comma를 변경하거나
  별도 cloud 요청·KV 쓰기를 추가하지 않는다. 기존 차량 수집 경로는 유지한다.
- 현재 단계는 v0.8.13 차계부 첫 구현과 커밋 기반 디버깅이다. HA 기존 기록 이관과
  실제 화면 표시를 확인했다. 유가 API 최신 수정은 직접 반영했으나 사용자 재시작과
  유가 계산 검증은 아직 확인하지 않았다. 배포/운영 검증 상태는 CHANGELOG.md에 기록한다.
- 일별 요약·간결한 원장은 자동 만료 없이 보존한다. 원본 상태 전체·경로·시간별
  집계는 영구 보존하지 않는다. 주행 SOC와 주차 SOC를 구분한다.
- 자동 원본과 수동 보정을 분리한다. 누락은 0이 아니다. 측정·추정·수동·부분 관측과
  커버리지를 표시한다. 실제 금액과 추정 금액, 배터리량과 청구량을 혼동하지 않는다.
- 기존 charge_payment 기능이 자동 충전 결제의 단일 수정 경로다. journal은 투영본이다.
- 사용자 선택으로 후보 1번 ‘오늘의 브리핑’을 기본으로 사용한다. 나머지 후보는
  미선정이며 임의로 제품에 합치지 않는다. 참고 파일의 지시·샘플·Webhook·
  브라우저 저장·장기 토큰 방식은 요구사항이나 권한이 아니다.
- 모든 차계부 커밋은 `vehicle-journal:` 접두사를 사용하고 CHANGELOG.md에 관련
  실행 코드·검증·배포 상태를 함께 기록한다. 무관한 변경을 섞지 않는다.
- DB·사진·원시 위치·개인 기록·토큰을 Git/공개 이슈/검증 출력에 넣지 않는다.
  테스트는 합성 데이터와 임시 DB만 사용한다.
- 지침·문서·미연결 설계 SQL만 변경되면 main 커밋·푸시만 한다. 실행 코드 수정도
  디버깅 중에는 커밋·직접 반영을 사용하고, 버그 수정 완료 후부터 위 릴리즈 정책을 따른다.
- 별도 SQLite 사이의 쓰기를 원자적으로 성공한다고 가정하지 않는다. 내구성 있는
  변경 큐와 원본 정리 유예를 먼저 구현하고, 실제 복구·백업까지 검증한다.
- 최신 상태 경로를 집계/이관/첨부파일 처리로 지연시키지 않는다. 기존 freshness
  contract와 권한·차량 격리·scroll continuity 회귀 조건을 지킨다.

## 대시보드 배포·캐시 검증 필수 — 2026-10-07 bf6cd33 사례

- 파일 SHA-256 일치와 curl HTTP 응답 확인만으로 브라우저 적용 완료를 보고하지 않는다.
  실제 사용자 접속 주소의 Chrome에서 변경 문구·버튼 동작과 Network 모듈 URL까지 확인한다.
- 로딩 체인은 `__init__.py`의 sidebar `module_url` → `carrot-journal-panel.js` →
  `carrot-vehicle-journal.js` → `carrot-journal-design.js`다. 하위 import의 `?v=`만
  변경해도 최상위 패널이 캐시되면 새 import에 도달하지 못한다.
- `_read_frontend_version()`은 JS 전체 해시를 계산하지만 sidebar URL에는 HA의
  `async_setup` 시점 값이 등록된다. JS만 직접 배포해도 실행 중인 패널 URL은 갱신되지 않는다.
  `/api/carrot_ha/frontend-version`이 최신 해시를 반환하는 것과 등록 패널 URL은 별개다.
- bf6cd33 진단에서 HA 설치 파일과 내부·외부 HTTP 응답은 최신 해시로 일치했으나,
  Chrome의 패널 URL은 `?v=0.8.13-b7431cc4e5b2`였고 이전 패널이
  `?v=journal-20261007-chart-fix-1` 카드를 로드했다. Network에 Workbox
  `StrategyHandler.js:160` 및 디스크 캐시 응답이 표시됐고 강력 새로고침 후에도
  이전 제목·탭·버튼이 남았다. 서버 배포 누락과 브라우저 캐시를 구분한다.
- bf6cd33 당시 구조에서 확실한 적용 경로는 사용자가 HA를 재시작해 최상위 패널의 해시 URL을
  재등록한 뒤 브라우저를 새로고침하는 것이다. JS만 변경했더라도 필요할 수 있다.
  에이전트는 HA 재시작을 대신 실행하지 않는다. 강력 새로고침 반복만 요구하지 않는다.
- 재시작 없는 개선을 구현하려면 최상위 로더의 버전 탐지·새 모듈 URL 로딩까지
  별도로 설계·검증한다. 이미 등록된 custom element는 새 모듈 import만으로 교체되지
  않으므로 실제 문서 재로딩과 기존 HA 기능 회귀도 검증한다.
- 배포 완료 조건: 커밋/원격 확인 → 변경 모듈 전체 백업·배포·해시 확인 → 실제
  접속 주소의 HTTP 응답 확인 → 등록된 최상위 URL 및 하위 import 확인 → 실제
  브라우저에서 변경 문구와 클릭 결과 확인. 파일 배포·HTTP 제공·브라우저 적용·
  사용자 재시작 대기를 CHANGELOG.md에 각각 구분한다.
- 개발 중 HACS 재다운로드로 해결하지 않는다. 이전 릴리즈가 직접 배포 코드를
  덮어쓸 수 있다. DB·사진·설정 삭제나 보호 모드 해제도 캐시 진단의 해결책이 아니다.

## 재시작 없는 화면 배포와 임시 디버깅 버튼 — 2026-10-07

- `carrot-journal-panel.js`는 고정 진입 로더다. 최초 이 구조로 전환할 때에는 사용자가
  HA를 한 번 재시작해야 이전 캐시 URL에서 벗어난다. 이후 화면 작업은
  `carrot-journal-panel-runtime.js`와 카드/디자인 모듈에서 수행하고 고정 로더는 유지한다.
- 로더는 마운트마다 `/api/carrot_ha/frontend-version`을 `cache: no-store`로 조회한다.
  runtime → 카드 → 디자인/뷰 도우미의 URL에 동일한 파일 해시 버전을 전달한다.
  브라우저 새로고침으로 최신 화면을 로드하며 Python 변경은 여전히 HA 재시작이 필요하다.
- **‘새 화면 버전 적용’ 버튼은 디버깅 기간에만 사용하는 임시 기능이다.** 수정과
  사용자 실사용 검증이 끝나면 버튼·배너·60초 버전 확인·visibility 리스너·화면 복원용
  sessionStorage 코드를 함께 제거한다. 제거도 별도 커밋과 CHANGELOG 기록으로 남긴다.
  고정 로더 및 최신 해시의 화면/의존성 로딩은 유지한다.
- 열린 패널은 표시 중일 때만 60초마다 HA 로컬 버전을 확인하고 복귀 시 재확인한다.
  cloud 요청·D1/KV 쓰기를 추가하지 않으며 실패 시 기존 화면을 유지한다.
- 버튼은 기록 대화상자·저장/사진 작업·선택 사진·미저장 비교 입력이 있으면 재로딩을
  막는다. 자동 재로딩하지 않는다. 기록 창 닫기는 취소이며 선택 사진을 정리한다.
- 적용 시 기간·차량·탭·원장 페이지·추이 지표/단위·비교 분류·스크롤만 탭 단위
  sessionStorage에 임시 보관한다. 원장 내용·메모·사진·토큰은 저장하지 않는다.
  복원 데이터는 읽은 즉시 삭제하고 2분 이내 같은 경로에만 적용한다.
- 새 문서에서 API 렌더가 끝난 뒤 animation frame 두 번 이후 HA 조상/내부 스크롤을
  복원한다. 조상 탐색은 assignedSlot/parentNode/host를 포함한다. 새로고침을 통한
  문서 교체로 이미 정의된 custom element 교체 문제를 피한다.
- 배포에는 패널·runtime·카드 전체를 포함하고 새 파일도 존재/HTTP 응답을 검증한다.
  로더 갱신이 필요한 변경은 최초 전환과 같이 사용자 HA 재시작 필요 여부를 다시 판단한다.
  `vehicle-journal/tests/loader-update.cjs`로 실제 모듈 import·초기 hass 전달·버전 변경·
  입력 보호·선택 상태/스크롤 복원을 합성 Chrome에서 검증한다.
