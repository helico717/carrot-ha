Comma 소프트웨어 GitHub 상태

IQ.drive를 쓰는 동안 업데이트는 이렇게 흘러갑니다

당근 때와 같은 구조입니다. 무거운 일(합치기·시험)은 GitHub가 하고, Comma는 시험을 통과한 결과만 받습니다. 보라색 단계는 아직 만들지 않은 부분입니다(이 프리뷰는 동작 설명용입니다).

이미 있음① IQ 원본에 새 버전IQ 개발자가 konn3kt Git의 release에 새 커밋을 올립니다.
우리가 손대지 않는 원본
새로 만들 것② GitHub 자동 작업하루 한 번 원본을 확인 → 새 버전이면 iq-ha의 "IQ 원본 버전 쪽지"를 새 번호로 바꿈 → HA 연동 시험(CI) → 통과할 때만 iq-ha에 올림.
실패하면 올리지 않고 알림만
이미 있음③ HA 터미널 카드가 알려줌Comma가 보고한 설치 커밋과 GitHub iq-ha 최신 커밋을 비교해 "N개 커밋 뒤처짐"과 최신 내용을 표시합니다.
사용자④ 버튼 두 번[📥 IQ.drive 업데이트] → 받기만 함(기기 파일 강제 덮어쓰기 없음) → [🔄 기기 재부팅]으로 적용.
당근파일럿일 때 (지금과 같음)
버튼: 📥 당근 Git Pull
git reset --hard && git pull --ff-only
IQ.drive일 때 (바뀌는 점)
버튼 이름이 📥 IQ.drive 업데이트로 바뀝니다.
git pull --ff-only && git submodule update --init --depth 1 -- vendor/iqpilot
reset --hard 없음. 기기에 변경이 있으면 지우지 않고 멈춥니다. IQ 원본도 쪽지에 적힌 버전으로 함께 받습니다.
아래는 실제 터미널 카드 코드입니다. Comma는 가상입니다(입력은 실제 기기로 가지 않음). ① [연결] → ② [🔍 업데이트 확인] → ③ [📥 IQ.drive 업데이트] 순서로 눌러 보세요. 상단에서 당근파일럿으로 바꾸면 버튼 이름과 명령이 원래대로 돌아갑니다.
